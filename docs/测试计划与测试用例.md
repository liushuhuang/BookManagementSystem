# 明月图书借阅管理系统 V1.0 测试计划与测试用例

## 1. 文档概述

### 1.1 文档目的

本文档基于《需求规格说明书》《PRD 产品需求文档》《系统概要设计说明书》《数据库设计说明书》《接口设计文档》和《详细设计说明书》编写，用于明确明月图书借阅管理系统 V1.0 的测试目标、测试范围、测试策略、测试环境、测试数据、准入准出标准、缺陷管理规则和核心测试用例。

本文档作为后续功能测试、接口测试、集成测试、回归测试、验收测试和软著材料整理的依据。

### 1.2 测试对象

测试对象为明月图书借阅管理系统 V1.0，覆盖管理端、读者端和后端接口能力。系统核心业务对象包括用户、角色、权限、系统配置、图书分类、图书资料、馆藏副本、借阅记录、归还记录、罚款记录和统计数据。

### 1.3 测试依据

1. `docs/需求规格说明书.md`
2. `docs/PRD产品需求文档.md`
3. `docs/系统概要设计说明书.md`
4. `docs/数据库设计说明书.md`
5. `docs/接口设计文档.md`
6. `docs/详细设计说明书.md`

### 1.4 测试原则

1. 以业务闭环为主线，重点验证图书入库、借阅、归还、逾期和罚款。
2. 以角色权限为边界，重点验证 `admin`、`librarian`、`reader` 的访问差异。
3. 以数据一致性为底线，重点验证 `book_copy.status`、`borrow_record.status` 和 `fine_record.status` 的联动。
4. 以接口设计为准绳，统一验证接口路径、请求参数、响应结构、错误码和权限控制。
5. 以可回归为目标，测试用例编号、前置条件、操作步骤和预期结果保持稳定。

## 3. 测试策略

### 3.1 测试类型

| 测试类型 | 目标 | 重点 |
| --- | --- | --- |
| 单元测试 | 验证 Service 层业务规则 | 唯一性、状态机、金额计算、权限判断 |
| 接口测试 | 验证 REST 接口契约 | 路径、方法、参数、响应、错误码 |
| 集成测试 | 验证多表联动 | 借阅、归还、罚款、角色权限绑定 |
| 功能测试 | 验证用户可完成业务操作 | 管理端和读者端核心功能 |
| 流程测试 | 验证完整业务闭环 | 入库、查询、借阅、归还、统计 |
| 权限测试 | 验证角色和本人数据边界 | 越权访问、禁用用户、令牌失效 |
| 数据一致性测试 | 验证数据库状态正确 | 副本状态、借阅状态、罚款状态 |
| 性能测试 | 验证基础响应能力 | 登录、分页查询、借阅、归还 |
| 回归测试 | 验证修复不破坏核心功能 | P0 用例和主流程用例 |

### 3.2 测试方法

1. 黑盒测试：按需求和接口文档验证输入输出。
2. 边界值测试：验证分页、最大借阅数量、逾期天数、金额边界。
3. 等价类测试：验证合法输入、非法输入、空值、重复值和状态冲突。
4. 场景测试：验证新书入库、读者借阅、正常归还、逾期归还、遗失处理。
5. 权限矩阵测试：验证不同角色访问同一接口的结果。
6. 数据库核对：核心流程执行后核对相关表状态和统计口径。

## 4. 测试环境

### 4.1 环境配置

| 项目 | 建议配置 |
| --- | --- |
| 操作系统 | Windows、Linux 或 macOS |
| 后端运行环境 | Java 8 或兼容版本 |
| 后端框架 | Spring Boot 2.7.x |
| 数据库 | MySQL 8.x |
| 缓存 | Redis，可用于令牌状态和权限缓存 |
| 接口测试工具 | Postman、Apifox、curl 或自动化测试框架 |
| 浏览器 | Chrome、Edge |
| 数据字符集 | `utf8mb4` |

### 4.2 测试环境要求

1. 测试数据库与开发数据库隔离。
2. 每轮测试前初始化基础角色、权限、配置和分类数据。
3. 每个测试用例应能明确依赖的数据，避免互相污染。
4. P0 主流程测试应使用固定测试账号和固定馆藏编号。
5. 涉及时间的逾期测试应使用可控的借阅时间和应还时间。

## 6. 准入与准出标准

### 6.1 测试准入标准

1. 需求、接口、数据库和详细设计文档已经确认。
2. 测试环境可访问，数据库连接正常。
3. 基础初始化数据可重复导入。
4. 登录认证接口可正常调用。
5. P0 模块接口已完成开发并部署到测试环境。

### 6.2 测试暂停标准

1. 登录认证不可用，导致大部分接口无法测试。
2. 数据库结构与设计文档严重不一致，影响核心流程测试。
3. 借阅或归还主流程阻塞，无法继续验证后续模块。
4. 测试环境频繁不可用，影响测试结果可信度。

### 6.3 测试准出标准

1. P0 功能用例执行通过率达到 100%。
2. P1 功能用例执行通过率不低于 95%。
3. 不存在阻塞级和严重级未关闭缺陷。
4. 与借阅、归还、罚款、权限相关的高风险缺陷全部关闭。
5. 主流程回归测试通过。
6. 测试报告完成并记录遗留风险。

## 7. 缺陷管理

### 7.1 缺陷严重级别

| 级别 | 名称 | 判定标准 |
| --- | --- | --- |
| S1 | 阻塞 | 系统无法登录、核心流程无法执行、数据严重错误 |
| S2 | 严重 | 权限越权、借阅归还状态错误、罚款金额错误 |
| S3 | 一般 | 单个功能异常、提示不准确、筛选结果局部错误 |
| S4 | 轻微 | 文案、样式、非核心交互问题 |

### 7.2 缺陷优先级

| 优先级 | 处理要求 |
| --- | --- |
| P0 | 必须立即修复，阻塞测试或上线 |
| P1 | 当前版本必须修复 |
| P2 | 可排入后续迭代，但需评估风险 |
| P3 | 低风险优化项 |

### 7.3 缺陷记录字段

缺陷记录至少包含：缺陷编号、标题、模块、严重级别、优先级、前置条件、复现步骤、实际结果、预期结果、测试环境、截图或日志、提交人、负责人、状态和关闭结论。

## 18. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 数据库结构与设计不一致 | 测试结果不可比对 | 测试前执行结构核对，核心表字段与数据库设计保持一致 |
| 测试数据污染 | 用例互相影响 | 为主流程准备独立数据，必要时每轮重置测试库 |
| 时间相关测试不稳定 | 逾期天数和罚款金额不稳定 | 使用固定应还时间和归还时间 |
| 权限配置错误 | 大量权限用例失败 | 先验证基础角色权限初始化，再执行功能用例 |
| 并发测试复现难 | 难以确认副本重复借出问题 | 使用固定副本和并发接口脚本验证条件更新 |
| 统计口径偏差 | 工作台数据不可信 | 统计接口结果与数据库聚合结果交叉核对 |

## 19. 测试结论标准

当 P0 主流程、权限边界、数据一致性和核心接口全部通过，且不存在阻塞级和严重级未关闭缺陷时，可认为系统 V1.0 达到测试通过标准。若存在 P1 或 P2 遗留问题，应在测试报告中明确问题范围、影响模块、规避方式和后续修复计划。
