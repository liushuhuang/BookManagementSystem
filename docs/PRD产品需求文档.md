## 2. 产品定位

明月图书借阅管理系统是一套面向学校图书室、中小型图书馆、企业资料室和社区阅览室的图书借阅管理产品。系统通过统一的 Web 化管理能力，帮助图书管理人员维护图书资料、管理馆藏副本、办理借阅归还、处理逾期罚款，并帮助读者查询图书和查看个人借阅状态。

V1.0 聚焦图书借阅管理核心闭环，不依赖任何既有代码结构或历史数据库设计。后续代码、数据库和接口均应围绕本文档定义的产品目标和业务流程重新设计。

## 3. 产品目标

### 3.1 业务目标

1. 建立统一、准确的图书资料和馆藏副本管理体系。
2. 标准化借阅、归还、逾期和罚款处理流程。
3. 降低人工台账、重复登记和库存不一致问题。
4. 帮助管理员快速掌握馆藏数量、可借数量、借出数量和逾期情况。
5. 帮助读者快速查询图书信息、可借状态和个人借阅记录。
6. 为后续预约、续借、通知、报表、多馆区等功能扩展预留产品空间。

### 3.2 用户目标

1. 超级管理员可以维护用户、角色、权限和系统基础配置。
2. 图书管理员可以快速完成图书入库、馆藏维护、借书、还书和逾期处理。
3. 普通读者可以快速找到目标图书，并清楚了解是否可借。
4. 普通读者可以随时查看自己的借阅状态、应还时间和罚款状态。

### 3.3 成功指标

| 指标 | 目标 |
| --- | --- |
| 新书入库效率 | 管理员可在 3 分钟内完成一本新书资料和馆藏副本录入 |
| 借阅办理效率 | 管理员可在 1 分钟内完成一次借阅登记 |
| 归还办理效率 | 管理员可在 1 分钟内完成一次归还登记 |
| 查询效率 | 读者可通过书名、ISBN、作者或分类快速定位图书 |
| 数据准确性 | 借阅和归还后，馆藏副本状态与借阅记录保持一致 |
| 权限准确性 | 普通读者不能访问管理端功能或其他读者数据 |

## 4. 目标用户

### 4.1 超级管理员

超级管理员负责系统基础管理和权限治理。

核心诉求：

1. 创建和维护系统用户。
2. 分配用户角色。
3. 维护角色权限。
4. 配置默认借阅天数、最大借阅数量和逾期罚款规则。
5. 查看全局业务数据。

### 4.2 图书管理员

图书管理员负责日常图书业务，是系统最高频的管理端用户。

核心诉求：

1. 维护图书分类。
2. 维护图书资料。
3. 管理每一本实际馆藏副本。
4. 办理读者借书和还书。
5. 查询逾期记录和罚款记录。
6. 查看库存和借阅统计。

### 4.3 普通读者

普通读者是系统的借阅用户。

核心诉求：

1. 查询图书资料。
2. 查看图书是否可借。
3. 查看本人借阅中、已归还和逾期记录。
4. 查看应还时间和罚款状态。
5. 维护个人基础资料。

## 7. 核心使用场景

### 7.1 新书资料录入和馆藏入库

图书管理员收到新书后，先录入图书资料，包括 ISBN、书名、作者、出版社、分类、简介、价格和页数等信息。随后根据实际册数录入馆藏副本，为每册书生成或填写唯一馆藏编号，并设置存放位置。入库完成后，读者可以查询到该图书及其可借数量。

### 7.2 读者查询图书

读者进入图书查询页面，通过书名、ISBN、作者或分类筛选图书。系统展示图书列表、图书详情和可借状态。读者可查看该图书是否存在可借馆藏副本。

### 7.3 管理员办理借书

读者到馆借书时，图书管理员选择读者和目标图书，系统校验读者状态、借阅数量、图书状态和副本状态。校验通过后，系统生成借阅记录，并将具体馆藏副本状态变更为借出。

### 7.4 管理员办理还书

读者归还图书时，图书管理员通过借阅编号、读者、图书或馆藏编号查询借阅记录。系统校验记录是否可归还，记录归还时间，判断是否逾期，更新借阅记录和馆藏副本状态。

### 7.5 逾期和罚款处理

系统根据应还时间识别逾期记录。读者归还逾期图书时，系统按逾期天数和罚款规则生成罚款记录。管理员可维护罚款金额、缴纳状态或免除状态，读者可查看本人罚款处理结果。

### 7.6 管理员查看工作台

管理员进入系统后，可查看图书总数、馆藏总册数、可借数量、借出数量、逾期记录数、未缴罚款数等关键指标，并跳转到相应业务页面处理。

## 8. 功能需求明细

### 8.1 登录认证

用户故事：

作为系统用户，我希望通过账号密码登录系统，以便访问自己有权限使用的功能。

功能说明：

1. 输入用户名和密码。
2. 校验必填项。
3. 校验账号状态。
4. 校验密码正确性。
5. 登录成功后进入对应角色页面。
6. 登录失败时展示统一失败提示。

验收标准：

1. 用户名为空不能提交。
2. 密码为空不能提交。
3. 错误用户名或密码不能登录。
4. 禁用用户不能登录。
5. 登录成功后只能访问已授权功能。

### 8.2 用户管理

用户故事：

作为超级管理员，我希望维护用户信息，以便控制谁可以使用系统。

功能说明：

1. 新增用户。
2. 查询用户列表。
3. 查看用户详情。
4. 修改用户资料。
5. 启用或禁用用户。
6. 删除用户。
7. 重置用户密码。
8. 设置读者编号和最大可借数量。

验收标准：

1. 用户名唯一。
2. 读者编号唯一。
3. 手机号和邮箱满足唯一性规则。
4. 新增或重置密码时必须加密存储。
5. 禁用用户不能登录和借阅。

### 8.3 角色权限管理

用户故事：

作为超级管理员，我希望维护角色和权限，以便不同用户只能访问被授权的功能。

功能说明：

1. 新增角色。
2. 修改角色。
3. 启用或禁用角色。
4. 新增权限。
5. 修改权限。
6. 为用户分配角色。
7. 为角色分配权限。

验收标准：

1. 角色编码唯一。
2. 权限编码唯一。
3. 禁用角色不参与权限判断。
4. 禁用权限不出现在可访问功能中。
5. 普通读者不能访问管理端功能。

### 8.4 系统配置

用户故事：

作为超级管理员，我希望配置基础借阅规则，以便系统按统一规则处理借阅和罚款。

功能说明：

1. 配置默认借阅天数。
2. 配置默认最大借阅数量。
3. 配置逾期每日罚款金额。
4. 启用或禁用配置项。

验收标准：

1. 新增借阅记录时使用当前有效借阅天数。
2. 借阅前校验读者当前借阅数量。
3. 逾期罚款金额可根据配置计算。
4. 历史借阅记录不因配置变更自动改变。

### 8.5 图书分类管理

用户故事：

作为图书管理员，我希望维护图书分类，以便图书可以按类别组织和查询。

功能说明：

1. 新增分类。
2. 修改分类。
3. 查询分类列表。
4. 支持父子分类。
5. 启用或禁用分类。
6. 删除分类。

验收标准：

1. 分类名称唯一。
2. 分类编码唯一。
3. 已被图书使用的分类不能物理删除。
4. 禁用分类不能绑定新图书。

### 8.6 图书资料管理

用户故事：

作为图书管理员，我希望维护图书资料，以便系统保存准确的书目信息。

功能说明：

1. 新增图书资料。
2. 修改图书资料。
3. 查询图书列表。
4. 查看图书详情。
5. 上架或下架图书。
6. 删除图书资料。

主要字段：

1. ISBN。
2. 书名。
3. 作者。
4. 出版社。
5. 出版日期。
6. 分类。
7. 封面。
8. 简介。
9. 价格。

验收标准：

1. ISBN 唯一。

3. 下架图书不能新增借阅。
4. 存在未归还副本时不能删除图书资料。

### 8.7 馆藏副本管理

用户故事：

作为图书管理员，我希望管理每一册实际馆藏，以便准确掌握库存和图书流转状态。

功能说明：

1. 为图书新增馆藏副本。
2. 设置馆藏编号。
3. 设置存放位置。
4. 修改副本状态。
5. 查询副本列表。
6. 查看副本借阅历史。

副本状态：

1. 可借。
2. 借出。
3. 下架。
4. 损坏。
5. 遗失。

验收标准：

1. 馆藏编号唯一。
2. 只有可借副本可以借出。
3. 借出副本不能重复借出。

用户故事：

## 9. 关键业务规则

### 9.1 用户规则

1. 用户名不能为空且唯一。
2. 读者编号唯一。
3. 密码必须加密存储。
4. 禁用用户不能登录和借阅。
5. 普通读者不能访问管理端功能。

### 9.2 图书规则

1. ISBN 不能为空且唯一。
2. 图书必须绑定有效分类。
3. 下架图书不能新增借阅。
4. 存在未归还副本时，图书资料不能删除。

### 9.3 馆藏规则

1. 馆藏编号不能为空且唯一。
2. 可借副本才能被借出。
3. 借出副本不能重复借出。
4. 损坏、遗失、下架副本不计入可借数量。
5. 库存数量由副本状态统计得出。

### 9.4 借阅规则

1. 借阅必须关联有效读者、图书和馆藏副本。
2. 借阅成功后记录借阅时间和应还时间。
3. 借阅成功后副本状态变更为借出。
4. 同一读者对同一本图书存在未归还记录时，可限制重复借阅。
5. 用户当前借阅数量不能超过规则限制。

### 9.5 归还规则

1. 已归还记录不能重复归还。
2. 归还必须记录实际归还时间。
3. 正常归还后副本状态恢复为可借。
4. 异常归还可将副本状态变更为损坏或遗失。

### 9.6 罚款规则

1. 超过应还时间未归还视为逾期。
2. 逾期罚款可根据逾期天数和每日罚款金额计算。
3. 罚款状态包括未缴纳、已缴纳、已免除。
4. 罚款记录不要求在线支付。

## 10. 页面与交互要求

### 10.1 通用要求

1. 列表页应支持分页。
2. 高频列表应支持关键词和条件筛选。
3. 新增、编辑页面应提供必填校验。
4. 删除、禁用、下架、归还等关键操作应有确认提示。
5. 操作成功或失败后应给出明确反馈。
6. 无权限功能不应展示给当前用户。

### 10.2 管理端要求

1. 菜单按业务模块组织。
2. 工作台展示关键指标和待处理事项。
3. 借阅和归还流程应尽量减少录入步骤。
4. 图书资料和馆藏副本应能从详情页互相跳转。
5. 状态字段应在列表中清晰展示。

### 10.3 读者端要求

1. 图书查询入口明显。
2. 图书详情页展示可借数量。
3. 我的借阅按借阅中、已归还、逾期分类展示。
4. 应还时间和逾期状态应突出展示。
5. 罚款状态应清楚可见。

## 11. 统计口径

| 指标 | 口径 |
| --- | --- |
| 图书总数 | 有效图书资料数量 |
| 馆藏总册数 | 有效馆藏副本数量 |
| 可借数量 | 状态为可借的馆藏副本数量 |
| 已借数量 | 状态为借出的馆藏副本数量 |
| 借阅中记录数 | 状态为借阅中的借阅记录数量 |
| 已归还记录数 | 状态为已归还的借阅记录数量 |
| 逾期记录数 | 超过应还时间未归还，或状态为逾期的记录数量 |
| 未缴罚款数 | 状态为未缴纳的罚款记录数量 |
| 分类图书数 | 按分类统计有效图书资料数量 |

## 12. 非功能要求

### 12.1 性能

1. 普通查询响应时间不超过 3 秒。
2. 登录、借阅、归还等核心操作响应时间不超过 5 秒。
3. 列表查询必须分页。
4. 高频条件查询应支持快速筛选。

### 12.2 安全

1. 密码加密存储。
2. 访问受保护功能需要登录凭证。
3. 管理端功能需要角色权限控制。
4. 普通读者只能访问本人数据。
5. 系统异常不暴露敏感内部信息。

### 12.3 稳定性

1. 借阅记录和馆藏副本状态必须保持一致。
2. 重复提交不应造成重复借阅或重复归还。
3. 业务失败时应给出明确提示。

### 12.4 可维护性

1. 用户、权限、图书、馆藏、借阅、罚款等模块边界清晰。
2. 业务规则应集中维护。
3. 系统配置应支持独立维护。

## 14. 风险与应对

| 风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 图书资料和馆藏副本概念混淆 | 库存和借阅状态不准确 | 产品和数据库层明确区分书目与单册副本 |
| 权限边界不清晰 | 可能出现越权访问 | V1.0 明确超级管理员、图书管理员、普通读者三类角色 |
| 借阅归还重复提交 | 可能导致副本状态错误 | 借阅和归还操作进行状态校验 |
| 逾期罚款规则复杂 | 增加开发和测试成本 | V1.0 只实现基础每日罚款和状态维护 |
| 统计口径不一致 | 管理端数据不可信 | PRD 明确统计口径，后续设计保持一致 |

## 15. 验收清单

1. 用户可以登录系统，错误账号或密码不能登录。
2. 禁用用户不能登录。
3. 超级管理员可以维护用户、角色和权限。
4. 超级管理员可以维护系统基础配置。
5. 图书管理员可以维护图书分类。
6. 图书管理员可以维护图书资料。
7. 图书管理员可以维护馆藏副本。
8. 系统可以按副本状态统计库存。
9. 系统可以办理借阅并将副本状态更新为借出。
10. 系统可以办理归还并按结果更新副本状态。
11. 系统可以识别逾期并维护罚款记录。
12. 读者可以查询图书和查看个人借阅记录。
13. 普通读者不能查看其他用户借阅记录。
14. 管理员可以查看全局统计数据。
15. 系统对必填、唯一性、状态、数量和权限规则进行校验。
