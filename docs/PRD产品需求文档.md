## 2. 产品概述

明月图书借阅管理系统是一套面向中小型图书馆、学校图书室和企业资料室的图书借阅管理产品。系统通过信息化方式管理图书资料、读者信息、库存数量、借阅记录和归还状态，帮助管理员减少人工登记工作，提高图书流转效率，并为读者提供便捷的图书查询和借阅记录查看能力。

V1.0 版本聚焦图书借阅管理的核心闭环：用户登录、图书维护、分类维护、库存维护、借阅办理、归还办理、逾期罚款记录和基础统计查询。

## 3. 产品目标

### 3.1 业务目标

1. 建立统一的图书资料管理入口，减少分散登记和重复维护。
2. 提供标准化借阅、归还流程，降低人工处理错误。
3. 让管理员能够实时掌握图书库存、借阅中记录和逾期情况。
4. 让读者能够快速查询图书信息和个人借阅状态。
5. 为课程设计、软著申报和后续系统扩展提供完整产品基础。

### 3.2 用户目标

1. 管理员可以快速完成图书入库、库存调整、借书和还书。
2. 读者可以快速找到目标图书，并了解是否可借。
3. 系统使用者可以清楚看到借阅状态、应还时间和罚款状态。
4. 超级管理员可以控制用户、角色和系统基础数据。

### 3.3 成功指标

1. 管理员能在 3 分钟内完成一本新书的录入和库存设置。
2. 管理员能在 1 分钟内完成一次借阅登记。
3. 管理员能在 1 分钟内完成一次归还登记。
4. 读者能通过书名、ISBN、作者或分类快速查询图书。
5. 借阅和归还后，库存数据与借阅记录保持一致。

## 4. 目标用户

### 4.1 超级管理员

超级管理员负责系统初始化、用户与角色维护、基础数据维护和全局监管。该角色关注系统是否安全、数据是否完整、权限是否可控。

典型诉求：

1. 创建管理员和普通读者账号。
2. 分配用户角色。
3. 禁用异常账号。
4. 查看全局业务数据。

### 4.2 图书管理员

图书管理员负责日常图书业务操作，是系统的高频使用者。该角色关注操作效率、查询效率和借阅数据准确性。

典型诉求：

1. 维护图书分类和图书信息。
2. 设置图书库存和存放位置。
3. 为读者办理借阅和归还。
4. 查询逾期记录和罚款状态。

### 4.3 普通读者

普通读者使用系统查询图书、查看库存状态和个人借阅记录。该角色关注信息是否清楚、查询是否方便、个人借阅状态是否准确。

典型诉求：

1. 查询图书是否存在、是否可借。
2. 查看本人借阅中、已归还和逾期记录。
3. 查看应还时间和罚款状态。
4. 维护个人基础资料。

## 5. 使用场景

### 5.1 新书入库

图书管理员收到新书后，在系统中录入书名、ISBN、作者、出版社、分类、简介、价格、页数等信息，并设置库存数量和存放位置。系统校验 ISBN 唯一性和分类有效性，保存成功后图书进入可查询状态。

### 5.2 读者借书

读者查询目标图书，确认图书可借后，由管理员办理借阅，或在系统规则允许时由读者发起借阅。系统校验用户状态、图书状态和库存数量，借阅成功后生成借阅记录并扣减可借库存。

### 5.3 读者还书

读者归还图书时，管理员查询该读者的借阅中记录并办理归还。系统记录归还时间，判断是否逾期，更新借阅状态、罚款信息和库存数量。

### 5.4 逾期处理

管理员查看逾期清单，系统展示逾期用户、图书、应还时间、逾期状态和罚款状态。读者归还图书后，管理员维护罚款金额和缴纳状态。

### 5.5 读者自助查询

读者登录系统后，可通过书名、ISBN、作者、分类等条件查询图书，查看图书详情、库存状态和本人借阅历史。

## 8. 功能需求明细

### 8.1 登录页

用户故事：

作为系统用户，我希望通过用户名和密码登录系统，以便进入自己有权限访问的功能页面。

功能说明：

1. 用户输入用户名和密码。
2. 系统校验必填项。
3. 系统校验账号状态和密码正确性。
4. 登录成功后进入对应角色页面。
5. 登录失败时显示统一错误提示。

验收标准：

1. 用户名为空时不能提交。
2. 密码为空时不能提交。
3. 用户名或密码错误时不能登录。
4. 禁用用户不能登录。
5. 登录成功后系统返回有效访问令牌。

### 8.2 工作台

用户故事：

作为管理员，我希望进入系统后看到关键业务数据，以便快速了解当前图书借阅情况。

功能说明：

1. 展示图书总数。
2. 展示可借图书数量。
3. 展示借阅中记录数量。
4. 展示逾期记录数量。
5. 支持跳转到图书、借阅、逾期等管理页面。

验收标准：

1. 管理员登录后可以看到工作台。
2. 工作台数据应与业务数据一致。
3. 普通读者不显示全局统计数据。

### 8.3 用户管理

用户故事：

作为超级管理员，我希望维护系统用户，以便控制谁可以使用系统以及使用哪些功能。

功能说明：

1. 新增用户。
2. 查询用户列表。
3. 查看用户详情。
4. 修改用户信息。
5. 启用或禁用用户。
6. 删除用户。
7. 分配用户角色。

验收标准：

1. 用户名、手机号、邮箱满足唯一性规则。
2. 新增用户时密码必须加密存储。
3. 被禁用用户无法登录。
4. 删除用户后，普通查询不再返回该用户。
5. 普通读者不能访问用户管理功能。

### 8.4 角色管理

用户故事：

作为超级管理员，我希望维护角色并为用户分配角色，以便不同用户获得不同操作权限。

功能说明：

1. 新增角色。
2. 修改角色。
3. 查询角色列表。
4. 启用或禁用角色。
5. 为用户绑定角色。

验收标准：

1. 角色名称和角色编码唯一。
2. 禁用角色不参与权限判断。
3. 只有超级管理员可以维护角色。

### 8.5 图书分类管理

用户故事：

作为图书管理员，我希望维护图书分类，以便图书可以按类别管理和查询。

功能说明：

1. 新增分类。
2. 修改分类。
3. 查询分类列表。
4. 启用或禁用分类。
5. 删除分类。
6. 支持父子分类结构。

验收标准：

1. 分类名称和分类编码唯一。
2. 顶级分类的父分类编号为 0。
3. 已被图书使用的分类不能直接物理删除。
4. 禁用分类不建议继续绑定新图书。

### 8.6 图书信息管理

用户故事：

作为图书管理员，我希望维护图书资料，以便系统中保存准确、完整的图书信息。

功能说明：

1. 新增图书。
2. 修改图书。
3. 查询图书列表。
4. 查看图书详情。
5. 上架或下架图书。
6. 删除图书。

主要字段：

1. 书名。
2. ISBN。
3. 作者。
4. 出版社。
5. 出版日期。
6. 分类。
7. 封面。
8. 简介。
9. 价格。
10. 页数。
11. 状态。

验收标准：

1. ISBN 唯一。
2. 图书必须绑定有效分类。
3. 下架图书不能被新增借阅。
4. 存在未归还记录的图书不能直接删除。
5. 读者可以查询上架图书。

### 8.7 库存管理

用户故事：

作为图书管理员，我希望维护图书库存，以便准确知道每本书有多少库存、多少可借、多少已借。

功能说明：

1. 设置图书总数量。
2. 设置图书可借数量。
3. 查看图书已借数量。
4. 设置存放位置。
5. 调整库存数量。

验收标准：

1. 库存数量不能为负数。
2. 可借数量加已借数量不能大于总数量。
3. 借阅成功后可借数量减少。
4. 归还成功后可借数量增加。
5. 可借数量为 0 时不能继续借出。

### 8.8 借阅管理

用户故事：

作为图书管理员，我希望为读者办理借书，以便系统记录图书借出情况并自动维护库存。

功能说明：

1. 选择读者。
2. 选择图书。
3. 校验用户状态。
4. 校验图书状态。
5. 校验库存数量。
6. 生成借阅记录。
7. 设置应还时间。

验收标准：

1. 禁用用户不能借书。
2. 下架图书不能借出。
3. 无可借库存时不能借出。
4. 借阅成功后生成状态为“借阅中”的记录。
5. 借阅成功后库存同步更新。

### 8.9 归还管理

用户故事：

作为图书管理员，我希望办理还书，以便系统更新借阅状态和库存。

功能说明：

1. 查询借阅中记录。
2. 选择待归还记录。
3. 记录归还时间。
4. 判断是否逾期。
5. 更新借阅状态。
6. 恢复可借库存。

验收标准：

1. 已归还记录不能重复归还。
2. 归还成功后状态变为“已归还”或保留逾期标识。
3. 归还成功后可借库存增加。
4. 逾期归还时系统记录罚款金额或罚款状态。

### 8.10 逾期与罚款管理

用户故事：

作为管理员，我希望查看逾期记录并维护罚款状态，以便追踪逾期处理情况。

功能说明：

1. 查询逾期记录。
2. 查看逾期用户、图书、应还时间和归还时间。
3. 记录罚款金额。
4. 修改罚款缴纳状态。
5. 读者查看本人逾期和罚款状态。

验收标准：

1. 超过应还时间且未归还的记录可被识别为逾期。
2. 罚款状态包括未缴纳和已缴纳。
3. 普通读者只能查看自己的罚款记录。

### 8.11 我的借阅

用户故事：

作为普通读者，我希望查看自己的借阅记录，以便知道哪些图书正在借阅、何时应还、是否逾期。

功能说明：

1. 查看借阅中记录。
2. 查看已归还记录。
3. 查看逾期记录。
4. 查看应还时间、归还时间和罚款状态。

验收标准：

1. 读者只能查看自己的记录。
2. 借阅状态显示准确。
3. 应还时间和归还时间显示准确。

### 8.12 统计查询

用户故事：

作为管理员，我希望查看基础统计数据，以便掌握系统整体运行情况。

功能说明：

1. 图书总数统计。
2. 可借数量统计。
3. 已借数量统计。
4. 借阅中记录统计。
5. 已归还记录统计。
6. 逾期记录统计。
7. 按分类统计图书数量。

验收标准：

1. 统计数据与实际业务数据一致。
2. 管理端可查看全局统计。
3. 读者端不展示全局统计。

## 9. 关键业务规则

### 9.1 用户规则

1. 用户名不能为空且唯一。
2. 密码不能为空，并且必须加密存储。
3. 禁用用户不能登录，不能新增借阅。
4. 普通读者不能访问管理端功能。

### 9.2 图书规则

1. ISBN 不能为空且唯一。
2. 图书必须归属有效分类。
3. 下架图书不能新增借阅。
4. 存在未归还记录的图书不能直接删除。

### 9.3 库存规则

1. 总数量、可借数量、已借数量不能为负数。
2. 可借数量加已借数量不能大于总数量。
3. 借阅成功时，可借数量减 1，已借数量加 1。
4. 归还成功时，可借数量加 1，已借数量减 1。

### 9.4 借阅规则

1. 借阅记录必须关联有效用户和有效图书。
2. 借阅成功后记录借阅时间和应还时间。
3. 借阅状态包括借阅中、已归还、逾期。
4. 同一读者对同一本图书存在未归还记录时，可限制重复借阅。

### 9.5 罚款规则

1. 超过应还时间且未归还的记录视为逾期。
2. 罚款金额可由系统计算或管理员录入。
3. 罚款状态包括未缴纳和已缴纳。

## 10. 页面与交互要求

### 10.1 通用要求

1. 所有列表页应支持分页。
2. 常用列表页应支持关键词或条件筛选。
3. 新增、编辑页面应提供必填校验。
4. 删除、禁用、下架、归还等关键操作应有确认提示。
5. 操作成功或失败后应给出明确反馈。
6. 普通读者不展示无权限入口。

### 10.2 管理端交互要求

1. 管理端菜单按业务模块组织。
2. 高频操作入口应清晰，例如新增图书、办理借阅、办理归还。
3. 列表中应突出状态字段，例如图书状态、借阅状态、罚款状态。
4. 借阅和归还流程应尽量减少录入步骤。

### 10.3 读者端交互要求

1. 图书查询入口应明显。
2. 图书详情页应展示库存状态。
3. 我的借阅页面应区分借阅中、已归还和逾期。
4. 应还时间和逾期状态应醒目展示。

## 11. 数据埋点与统计口径

V1.0 不强制建设复杂埋点系统，但应明确统计口径，便于后续扩展。

| 指标 | 口径 |
| --- | --- |
| 图书总数 | 未逻辑删除的图书数量 |
| 可借数量 | 库存表中可借数量汇总 |
| 已借数量 | 库存表中已借数量汇总 |
| 借阅中记录数 | 借阅状态为借阅中的记录数 |
| 已归还记录数 | 借阅状态为已归还的记录数 |
| 逾期记录数 | 超过应还时间且未归还，或状态为逾期的记录数 |
| 分类图书数 | 按分类统计未逻辑删除的图书数量 |

## 12. 非功能要求

### 12.1 性能

1. 普通查询在正常数据量下响应时间不超过 3 秒。
2. 登录、借阅、归还等核心操作响应时间不超过 5 秒。
3. 列表查询必须分页。

### 12.2 安全

1. 密码加密存储。
2. 接口访问需要登录令牌。
3. 管理端能力需要角色权限控制。
4. 普通读者只能访问本人数据。

### 12.3 稳定性

1. 借阅和归还操作必须保证库存与记录一致。
2. 重复提交不应造成库存重复扣减或重复恢复。
3. 系统异常应返回统一错误信息。

### 12.4 可维护性

1. 后端按控制层、服务层、数据访问层、实体层分层。
2. 统一封装响应结果和异常处理。
3. 配置项集中管理。

## 13. 版本规划

### 13.1 V1.0

完成图书借阅管理核心闭环，包括用户、角色、分类、图书、库存、借阅、归还、逾期罚款和基础统计。

### 13.2 V1.1

可扩展图书预约、续借、借阅规则配置和到期提醒。

### 13.3 V1.2

可扩展在线罚款缴纳、操作日志、统计报表和多馆区库存管理。

## 14. 风险与依赖

| 风险或依赖 | 影响 | 应对方式 |
| --- | --- | --- |
| 权限规则不清晰 | 可能导致用户越权访问 | V1.0 明确超级管理员、图书管理员、普通读者三类角色 |
| 库存更新不一致 | 影响借阅数据准确性 | 借阅和归还操作中同步维护库存与记录 |
| 逾期罚款规则复杂 | 增加开发和测试成本 | V1.0 仅记录基础罚款金额和缴纳状态 |
| 前后端页面范围不明确 | 影响开发排期 | PRD 明确管理端和读者端页面结构 |
| 数据初始化不足 | 影响演示和验收 | 提供默认角色、管理员和基础分类 |

## 15. 验收清单

1. 用户可以登录系统，错误账号或密码不能登录。
2. 管理员可以维护用户和角色。
3. 管理员可以维护图书分类。
4. 管理员可以新增、修改、查询、上下架图书。
5. 管理员可以维护图书库存。
6. 系统可以办理借阅并扣减库存。
7. 系统可以办理归还并恢复库存。
8. 系统可以识别逾期并记录罚款状态。
9. 读者可以查询图书和查看个人借阅记录。
10. 普通读者不能查看其他用户借阅记录。
11. 管理员可以查看基础统计数据。
12. 系统对必填、唯一性、状态和数量规则进行校验。
13. 系统异常和业务失败返回明确提示。
