# 明月图书借阅管理系统 V1.0 需求规格说明书

## 1. 文档概述

### 1.1 文档目的

本文档用于说明“明月图书借阅管理系统 V1.0”的建设目标、业务范围、用户角色、功能需求、数据需求、非功能需求和验收标准，为系统设计、开发、测试、课程设计说明及软件著作权材料整理提供依据。

### 1.2 系统名称

明月图书借阅管理系统 V1.0，简称 BMS。

### 1.3 适用范围

系统面向中小型图书馆、学校图书室、企业资料室等场景，提供图书信息维护、读者管理、图书借阅、图书归还、库存维护、分类管理、用户权限管理和基础统计查询等能力。

### 1.4 建设目标

系统建设目标如下：

1. 实现图书资料的集中化、规范化管理。
2. 支持读者在线查询图书、借阅图书和查看个人借阅记录。
3. 支持管理员维护图书、分类、库存、读者和借阅记录。
4. 减少人工登记和纸质台账，提高借阅处理效率。
5. 通过角色权限控制保障系统数据安全。
6. 为后续扩展预约、续借、罚款统计、报表分析等功能预留数据基础。

## 2. 项目背景

传统图书借阅管理依赖人工登记，容易出现图书信息维护不及时、库存不准确、借阅记录难追踪、逾期统计困难等问题。随着图书数量和读者数量增长，需要通过信息化系统统一管理图书生命周期、读者信息和借阅流程。

明月图书借阅管理系统以 Web 服务方式提供核心业务能力，后端采用 Java、Spring Boot、MyBatis-Plus、MySQL、Redis 等技术实现，支持通过接口为管理端和读者端提供数据服务。

## 3. 用户角色

### 3.1 超级管理员

超级管理员拥有系统最高权限，负责系统初始化、管理员维护、角色权限分配、基础数据维护和全局业务监管。

主要操作包括：

1. 登录系统。
2. 管理系统用户和角色。
3. 维护图书分类、图书信息和库存信息。
4. 查看全部借阅记录和统计数据。
5. 禁用异常用户或下架异常图书。

### 3.2 图书管理员

图书管理员负责日常图书业务处理。

主要操作包括：

1. 维护图书分类。
2. 新增、修改、查询、上下架图书。
3. 维护图书库存和存放位置。
4. 办理借书、还书和逾期处理。
5. 查询读者借阅情况。

### 3.3 普通读者

普通读者是系统的主要借阅用户。

主要操作包括：

1. 登录系统。
2. 查询图书信息和库存状态。
3. 查看个人资料。
4. 查看个人借阅记录、应还日期、归还状态和罚款状态。
5. 按系统规则发起借阅申请或由管理员代办借阅。

## 4. 总体业务范围

系统 V1.0 覆盖以下业务模块：

1. 登录认证模块。
2. 用户与角色管理模块。
3. 图书分类管理模块。
4. 图书信息管理模块。
5. 图书库存管理模块。
6. 图书借阅与归还模块。
7. 逾期与罚款管理模块。
8. 查询与统计模块。
9. 系统基础配置与异常处理模块。

系统 V1.0 不强制包含在线支付、短信通知、复杂审批流、图书采购流程、多馆区调拨和移动端原生应用。这些功能可作为后续版本扩展。

## 5. 功能需求

### 5.1 登录认证

系统应提供用户登录能力。用户输入用户名和密码后，系统验证用户身份，验证通过后返回登录凭证。

功能要求：

1. 用户名和密码不能为空。
2. 密码应采用加密方式存储，不允许明文保存。
3. 登录失败时应返回统一错误提示，避免暴露用户名是否存在。
4. 登录成功后生成访问令牌，用于后续接口访问。
5. 禁用用户不得登录系统。
6. 系统应支持登录状态校验和令牌过期处理。

### 5.2 用户管理

系统应支持对用户信息进行维护。用户包括管理员、图书管理员和普通读者。

功能要求：

1. 支持新增用户，记录用户名、密码、真实姓名、手机号、邮箱、头像、状态等信息。
2. 支持按用户编号查询用户详情。
3. 支持按用户名、真实姓名、手机号、状态等条件分页查询用户。
4. 支持修改用户基本资料。
5. 支持启用、禁用用户。
6. 支持逻辑删除用户，删除后不再参与正常业务查询。
7. 支持用户角色分配。
8. 用户名、手机号、邮箱应满足唯一性要求。

### 5.3 角色权限管理

系统应通过角色区分不同用户的操作范围。

功能要求：

1. 支持角色数据维护，包含角色名称、角色编码、角色描述和状态。
2. 支持为用户绑定一个或多个角色。
3. 支持根据角色控制管理端功能访问。
4. 系统默认包含超级管理员和普通用户角色。
5. 被禁用角色不应继续参与权限判断。

### 5.4 图书分类管理

系统应支持图书分类维护，用于图书归类和查询筛选。

功能要求：

1. 支持新增分类，记录分类名称、分类编码、父分类、排序号、描述和状态。
2. 支持修改分类信息。
3. 支持启用、禁用分类。
4. 支持逻辑删除分类。
5. 支持树形分类结构，顶级分类的父分类编号为 0。
6. 分类名称和分类编码应保持唯一。
7. 已被图书使用的分类不应直接物理删除。

### 5.5 图书信息管理

系统应支持图书基础信息维护。

功能要求：

1. 支持新增图书，记录书名、ISBN、作者、出版社、出版日期、分类、封面、简介、价格、页数和状态。
2. 支持修改图书信息。
3. 支持按书名、ISBN、作者、出版社、分类、状态等条件查询图书。
4. 支持图书详情查看。
5. 支持图书上架和下架。
6. 支持逻辑删除图书。
7. ISBN 应保持唯一。
8. 下架图书不允许被新增借阅。
9. 删除图书前应校验是否存在未归还记录。

### 5.6 图书库存管理

系统应维护每本图书的库存数据。

功能要求：

1. 支持为图书设置库存总量、可借数量、已借数量和存放位置。
2. 支持库存数量调整。
3. 借书成功后，可借数量减少，已借数量增加。
4. 还书成功后，可借数量增加，已借数量减少。
5. 库存数量不得为负数。
6. 可借数量与已借数量之和不得大于总数量。
7. 当可借数量为 0 时，系统不允许继续借出该图书。

### 5.7 图书借阅管理

系统应支持图书借阅登记。

功能要求：

1. 支持管理员为读者办理借书。
2. 支持读者在规则允许范围内发起借阅。
3. 借阅时应校验用户状态、图书状态、库存数量和是否存在限制条件。
4. 借阅成功后生成借阅记录，记录图书、用户、借阅时间、应还时间和状态。
5. 借阅状态包括借阅中、已归还、逾期。
6. 同一读者对同一本图书存在未归还记录时，系统可限制重复借阅。
7. 系统应支持按用户、图书、状态、借阅时间范围查询借阅记录。

### 5.8 图书归还管理

系统应支持图书归还登记。

功能要求：

1. 支持管理员办理还书。
2. 还书时应校验借阅记录是否存在、是否已归还。
3. 归还成功后记录归还时间。
4. 归还成功后更新借阅状态和库存数量。
5. 若归还时间晚于应还时间，系统应标记逾期并计算罚款金额。
6. 已归还记录不得重复归还。

### 5.9 逾期与罚款管理

系统应支持基础逾期和罚款记录。

功能要求：

1. 系统应能识别超过应还时间且未归还的借阅记录。
2. 系统应支持记录罚款金额。
3. 系统应支持罚款状态维护，包括未缴纳和已缴纳。
4. 管理员可按用户、图书、状态查询逾期记录。
5. 普通读者可查看自己的逾期记录和罚款状态。

### 5.10 查询与统计

系统应提供基础查询和统计能力。

功能要求：

1. 支持图书总数、可借数量、已借数量统计。
2. 支持借阅中、已归还、逾期记录统计。
3. 支持按分类统计图书数量。
4. 支持按时间范围查询借阅记录。
5. 支持查询个人借阅历史。
6. 管理端可查看全局统计，读者端仅可查看个人数据。

## 6. 业务流程

### 6.1 用户登录流程

1. 用户进入登录页面。
2. 用户输入用户名和密码。
3. 系统校验输入项。
4. 系统查询用户信息并校验密码。
5. 校验通过后生成访问令牌。
6. 用户进入对应角色的系统页面。
7. 校验失败时系统提示登录失败。

### 6.2 图书入库流程

1. 管理员录入图书基本信息。
2. 系统校验 ISBN、分类、必填字段和数据格式。
3. 管理员录入库存总量和存放位置。
4. 系统保存图书信息。
5. 系统生成或更新库存记录。
6. 图书进入可查询、可借阅状态。

### 6.3 图书借阅流程

1. 用户或管理员查询目标图书。
2. 系统展示图书详情和可借数量。
3. 发起借阅操作。
4. 系统校验用户状态、图书状态、库存状态和借阅规则。
5. 校验通过后生成借阅记录。
6. 系统扣减可借库存并增加已借数量。
7. 系统返回借阅成功信息和应还时间。

### 6.4 图书归还流程

1. 管理员查询借阅记录。
2. 管理员选择待归还记录。
3. 系统校验记录是否有效且未归还。
4. 系统记录归还时间。
5. 系统判断是否逾期。
6. 系统更新借阅状态、罚款信息和库存数量。
7. 系统返回归还处理结果。

### 6.5 逾期处理流程

1. 系统根据当前时间和应还时间识别逾期记录。
2. 管理员查看逾期清单。
3. 用户归还图书后，系统计算或记录罚款金额。
4. 管理员维护罚款缴纳状态。
5. 用户可查看逾期和罚款处理结果。

## 7. 数据需求

### 7.1 用户数据

用户数据用于记录系统登录账号和人员基础信息，主要字段包括用户编号、用户名、密码、真实姓名、手机号、邮箱、头像、状态、创建时间、更新时间和逻辑删除标识。

### 7.2 角色数据

角色数据用于权限划分，主要字段包括角色编号、角色名称、角色编码、角色描述、状态、创建时间、更新时间和逻辑删除标识。

### 7.3 用户角色关联数据

用户角色关联数据用于描述用户和角色之间的绑定关系，主要字段包括关联编号、用户编号、角色编号和创建时间。

### 7.4 图书分类数据

图书分类数据用于管理图书所属类别，主要字段包括分类编号、分类名称、分类编码、父分类编号、排序号、描述、状态、创建时间、更新时间和逻辑删除标识。

### 7.5 图书数据

图书数据用于记录图书基础资料，主要字段包括图书编号、书名、ISBN、作者、出版社、出版日期、分类编号、封面地址、简介、价格、页数、状态、创建时间、更新时间和逻辑删除标识。

### 7.6 库存数据

库存数据用于记录图书数量和存放位置，主要字段包括库存编号、图书编号、总数量、可借数量、已借数量、存放位置、创建时间和更新时间。

### 7.7 借阅数据

借阅数据用于记录图书借出和归还全过程，主要字段包括借阅编号、图书编号、用户编号、借阅时间、应还时间、归还时间、借阅状态、罚款金额、罚款状态、备注、创建时间和更新时间。

### 7.8 数据约束

1. 用户名、手机号、邮箱应具备唯一性约束。
2. 角色名称、角色编码应具备唯一性约束。
3. 分类名称、分类编码应具备唯一性约束。
4. ISBN 应具备唯一性约束。
5. 图书必须归属于有效分类。
6. 库存必须关联有效图书。
7. 借阅记录必须关联有效用户和有效图书。
8. 涉及删除的核心业务数据应优先采用逻辑删除。

## 8. 非功能需求

### 8.1 性能需求

1. 普通查询接口在正常数据量下响应时间应控制在 3 秒以内。
2. 登录、借阅、归还等核心操作在正常网络和数据库状态下响应时间应控制在 5 秒以内。
3. 系统应支持分页查询，避免一次性加载大量数据。
4. 常用查询条件应结合数据库索引进行优化。

### 8.2 安全需求

1. 用户密码必须加密存储。
2. 系统应通过令牌机制校验登录状态。
3. 管理端接口应进行权限控制。
4. 普通读者不得访问其他用户的个人借阅数据。
5. 系统应对关键输入参数进行合法性校验。
6. 登录失败、业务异常和系统异常应返回统一格式结果。

### 8.3 可靠性需求

1. 借阅和归还操作应保证库存和借阅记录一致。
2. 对库存变更、借阅状态变更等关键操作应避免重复提交造成数据错误。
3. 数据库连接异常、缓存异常等情况应有明确错误处理。
4. 系统应保留必要的创建时间和更新时间，便于追踪数据变化。

### 8.4 易用性需求

1. 系统功能菜单应按业务模块组织。
2. 查询条件应符合图书管理人员和读者的常用操作习惯。
3. 表单录入应提供必填校验和格式校验。
4. 对新增、修改、删除、借阅、归还等操作应提供明确反馈。

### 8.5 可维护性需求

1. 后端代码应按控制层、服务层、数据访问层和实体层分层组织。
2. 公共响应、异常处理、分页查询和权限校验应尽量统一封装。
3. 系统配置应集中管理，便于不同环境部署。
4. 数据库表结构应命名清晰，字段含义明确。

### 8.6 兼容性需求

1. 后端运行环境应支持 Java 8。
2. 数据库应支持 MySQL 8.x。
3. 系统接口应采用 HTTP/JSON 方式，便于 Web 前端或其他客户端接入。
4. 系统应支持在 Windows 或 Linux 常见服务器环境中部署。

## 9. 运行环境

### 9.1 软件环境

1. JDK：Java 8。
2. 后端框架：Spring Boot 2.7.x。
3. 持久层框架：MyBatis-Plus。
4. 数据库：MySQL 8.x。
5. 缓存服务：Redis。
6. 构建工具：Maven。
7. 接口数据格式：JSON。

### 9.2 硬件环境

课程设计或中小型部署场景建议配置如下：

1. CPU：2 核及以上。
2. 内存：4 GB 及以上。
3. 磁盘：20 GB 可用空间及以上。
4. 网络：支持局域网或互联网访问。

## 10. 接口与交互要求

系统应通过统一接口格式与前端交互。

统一响应应包含处理状态、提示信息和业务数据。业务成功时返回业务数据，业务失败时返回明确错误信息。系统异常不应直接暴露底层堆栈信息。

核心接口范围包括：

1. 登录接口。
2. 用户新增、修改、查询、禁用接口。
3. 角色维护和用户角色绑定接口。
4. 图书分类新增、修改、查询、删除接口。
5. 图书新增、修改、查询、上下架、删除接口。
6. 库存查询和调整接口。
7. 借阅办理、归还办理、借阅记录查询接口。
8. 逾期记录查询和罚款状态维护接口。
9. 统计数据查询接口。

## 11. 权限要求

权限控制应遵循最小权限原则。

1. 未登录用户只能访问登录接口和允许公开查询的基础信息。
2. 普通读者只能查看图书公开信息和本人借阅数据。
3. 图书管理员可维护图书、库存、分类和借阅记录。
4. 超级管理员可维护用户、角色和全局业务数据。
5. 禁用用户和禁用角色不得继续访问受保护功能。

## 12. 验收标准

系统满足以下条件时，可认为 V1.0 需求达到验收要求：

1. 用户可通过正确账号密码登录系统。
2. 错误账号或错误密码无法登录系统。
3. 管理员可新增、查询和维护用户信息。
4. 管理员可维护图书分类。
5. 管理员可新增、修改、查询、上下架图书。
6. 系统可维护图书库存，库存数量满足业务约束。
7. 系统可完成借阅登记，并正确扣减库存。
8. 系统可完成归还登记，并正确恢复库存。
9. 系统可识别逾期记录并记录罚款状态。
10. 普通读者只能查看本人相关信息和借阅记录。
11. 管理端可查询全局借阅记录和基础统计数据。
12. 系统能够对必填项、唯一性、状态和数量等关键规则进行校验。
13. 系统异常返回统一格式，不影响主要业务流程。
