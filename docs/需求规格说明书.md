# 明月图书借阅管理系统 V1.0 需求规格说明书

## 1. 文档概述

### 1.1 文档目的

本文档用于定义“明月图书借阅管理系统 V1.0”的业务目标、用户角色、功能需求、业务规则、数据需求、非功能需求和验收标准，为后续产品设计、数据库设计、接口设计、详细设计、开发实现、测试验收、课程设计和软件著作权材料整理提供依据。

本文档只描述系统应满足的业务需求，不依赖任何既有代码、既有数据库表或历史设计文件。后续系统实现、数据库结构和接口设计均应以本文档及配套 PRD 为需求基线。

### 1.2 系统名称

明月图书借阅管理系统 V1.0，简称 BMS。

### 1.3 适用范围

系统适用于学校图书室、中小型图书馆、企业资料室、社区阅览室等图书借阅管理场景。系统面向管理员和读者提供图书资料维护、馆藏管理、图书查询、借阅登记、归还处理、逾期管理、罚款记录、用户权限管理和统计查询等功能。

### 1.4 术语说明

| 术语 | 说明 |
| --- | --- |
| 图书资料 | 表示一种图书的书目信息，如书名、ISBN、作者、出版社、分类等 |
| 馆藏副本 | 表示图书馆实际拥有的一册书，每册书应有唯一馆藏编号 |
| 借阅记录 | 记录读者借出、应还、归还、逾期等全过程 |
| 读者 | 具备图书查询和借阅资格的普通用户 |
| 图书管理员 | 负责日常图书、馆藏、借阅、归还和逾期处理的业务人员 |
| 超级管理员 | 负责系统用户、角色、权限和全局基础数据维护的管理人员 |

## 2. 项目背景

传统图书借阅管理依赖人工登记和纸质台账，容易出现图书资料维护不及时、馆藏数量不准确、借阅记录难追踪、逾期处理困难、统计数据滞后等问题。随着馆藏数量和读者数量增加，需要通过信息化系统统一管理图书资料、馆藏副本、读者信息和借阅流程。

明月图书借阅管理系统 V1.0 聚焦图书借阅业务的核心闭环，目标是提升图书入库、查询、借阅、归还、逾期处理和统计分析的效率与准确性。

## 3. 建设目标

系统建设目标如下：

1. 建立统一的图书资料和馆藏副本管理体系。
2. 支持读者快速查询图书资料、可借状态和个人借阅记录。
3. 支持图书管理员高效办理借书、还书、逾期和罚款处理。
4. 支持超级管理员维护用户、角色和权限。
5. 通过规则校验降低库存错误、重复借阅、重复归还等问题。
6. 支持基础统计查询，帮助管理人员掌握图书流转情况。
7. 为预约、续借、通知、报表、多馆区等后续功能预留业务扩展空间。

## 4. 用户角色

### 4.1 超级管理员

超级管理员拥有系统最高管理权限，负责系统基础配置、用户管理、角色权限分配和全局数据监管。

主要职责：

1. 登录系统。
2. 新增、修改、禁用、删除系统用户。
3. 维护角色和权限。
4. 为用户分配角色。
5. 查看全局图书、馆藏、借阅、逾期和罚款数据。
6. 维护系统基础参数。

### 4.2 图书管理员

图书管理员负责日常图书业务处理，是管理端的主要操作人员。

主要职责：

1. 维护图书分类。
2. 维护图书资料。
3. 管理馆藏副本和存放位置。
4. 为读者办理借阅。
5. 办理图书归还。
6. 查询借阅记录、逾期记录和罚款记录。
7. 查看图书库存和借阅统计。

### 4.3 普通读者

普通读者是系统的借阅用户，主要使用读者端功能。

主要职责：

1. 登录系统。
2. 查询图书资料和可借状态。
3. 查看图书详情。
4. 查看个人资料。
5. 查看本人借阅中、已归还、逾期和罚款记录。
6. 在系统规则允许时发起借阅申请。

## 5. 业务范围

### 5.1 V1.0 范围内

系统 V1.0 覆盖以下模块：

1. 登录认证模块。
2. 用户管理模块。
3. 角色权限模块。
4. 图书分类模块。
5. 图书资料模块。
6. 馆藏副本和库存模块。
7. 借阅管理模块。
8. 归还管理模块。
9. 逾期与罚款模块。
10. 查询与统计模块。
11. 系统基础配置模块。

### 5.2 V1.0 范围外

以下能力不作为 V1.0 必须交付内容，可在后续版本扩展：

1. 在线支付罚款。
2. 短信、邮件、微信等消息通知。
3. 图书预约。
4. 图书续借。
5. 图书采购审批。
6. 多馆区调拨。
7. 数据可视化大屏。
8. 原生移动端应用。
9. 操作日志审计。

## 6. 功能需求

### 6.1 登录认证

系统应提供统一登录认证能力。

功能要求：

1. 用户可通过用户名和密码登录系统。
2. 用户名和密码不能为空。
3. 密码必须加密存储，不允许明文保存。
4. 登录失败时应给出统一失败提示。
5. 禁用用户不得登录。
6. 登录成功后系统应生成登录凭证。
7. 受保护功能必须校验登录状态。
8. 登录凭证过期或无效时，系统应要求用户重新登录。

### 6.2 用户管理

系统应支持对系统用户和读者资料进行管理。

功能要求：

1. 支持新增用户。
2. 支持查看用户详情。
3. 支持按用户名、真实姓名、手机号、读者编号、状态等条件查询用户。
4. 支持分页查询用户列表。
5. 支持修改用户基础资料。
6. 支持重置用户密码。
7. 支持启用和禁用用户。
8. 支持删除用户，删除后不再出现在正常业务列表中。
9. 支持设置读者编号和最大可借数量。
10. 用户名、手机号、邮箱、读者编号应满足唯一性要求。

### 6.3 角色权限管理

系统应通过角色和权限控制用户可访问的功能范围。

功能要求：

1. 支持维护角色名称、角色编码、角色描述和角色状态。
2. 支持为用户分配一个或多个角色。
3. 支持维护权限名称、权限编码、权限类型和权限状态。
4. 支持为角色分配权限。
5. 支持按角色控制菜单、页面和关键操作访问。
6. 默认角色应包括超级管理员、图书管理员、普通读者。
7. 禁用角色或禁用权限不得继续参与权限判断。

### 6.4 图书分类管理

系统应支持图书分类维护，用于图书归类和查询筛选。

功能要求：

1. 支持新增分类。
2. 支持修改分类名称、分类编码、父分类、排序号、描述和状态。
3. 支持查询分类列表。
4. 支持树形分类结构。
5. 支持启用和禁用分类。
6. 支持删除分类。
7. 分类名称和分类编码应保持唯一。
8. 已被图书资料使用的分类不得直接物理删除。
9. 禁用分类不得继续绑定新图书。

### 6.5 图书资料管理

系统应支持图书书目信息维护。

功能要求：

1. 支持新增图书资料。
2. 支持修改图书名称、ISBN、作者、出版社、出版日期、分类、封面、简介、价格、页数和状态。
3. 支持图书详情查看。
4. 支持按书名、ISBN、作者、出版社、分类、状态等条件查询图书。
5. 支持分页查询图书列表。
6. 支持图书上架和下架。
7. 支持删除图书资料。
8. ISBN 应保持唯一。
9. 图书必须归属有效分类。
10. 下架图书不得新增借阅。
11. 存在未归还馆藏副本时，图书资料不得删除。

### 6.6 馆藏副本和库存管理

系统应支持对实际馆藏副本进行管理。库存数量应由馆藏副本状态统计得到。

功能要求：

1. 支持为图书资料新增馆藏副本。
2. 每个馆藏副本应具备唯一馆藏编号。
3. 支持维护馆藏副本的存放位置。
4. 支持设置副本状态，包括可借、借出、下架、损坏、遗失。
5. 支持按图书、馆藏编号、位置、状态查询副本。
6. 支持统计图书总册数、可借册数、借出册数、下架册数、损坏册数和遗失册数。
7. 只有可借状态的副本允许借出。
8. 借阅成功后副本状态应变为借出。
9. 归还成功后副本状态应按归还结果恢复为可借或变更为损坏、遗失等状态。

### 6.7 借阅管理

系统应支持读者借阅图书。

功能要求：

1. 支持图书管理员为读者办理借书。
2. 支持读者在规则允许范围内发起借阅申请。
3. 借阅时应校验读者状态是否正常。
4. 借阅时应校验读者当前借阅数量是否超过限制。
5. 借阅时应校验图书是否上架。
6. 借阅时应校验是否存在可借馆藏副本。
7. 借阅时可限制同一读者重复借阅同一本未归还图书。
8. 借阅成功后生成借阅记录。
9. 借阅记录应包含借阅编号、读者、图书、馆藏副本、借阅时间、应还时间、状态和办理人。
10. 借阅成功后应同步更新馆藏副本状态。

### 6.8 归还管理

系统应支持图书归还处理。

功能要求：

1. 支持图书管理员办理还书。
2. 支持按读者、图书、馆藏编号、借阅编号查询待归还记录。
3. 归还时应校验借阅记录是否存在。
4. 归还时应校验记录是否已归还。
5. 归还成功后记录实际归还时间。
6. 归还成功后更新借阅状态。
7. 归还成功后更新馆藏副本状态。
8. 若归还时间晚于应还时间，系统应识别逾期。
9. 已归还记录不得重复归还。

### 6.9 逾期与罚款管理

系统应支持逾期识别和罚款记录。

功能要求：

1. 系统应能识别超过应还时间且未归还的借阅记录。
2. 系统应支持按读者、图书、状态、时间范围查询逾期记录。
3. 系统应支持记录罚款类型、罚款金额、逾期天数和处理状态。
4. 罚款状态应包括未缴纳、已缴纳、已免除。
5. 管理员可维护罚款金额和罚款状态。
6. 读者可查看本人逾期记录和罚款状态。
7. V1.0 不要求接入在线支付。

### 6.10 查询与统计

系统应提供基础查询和统计能力。

功能要求：

1. 支持图书总数统计。
2. 支持馆藏总册数统计。
3. 支持可借、借出、下架、损坏、遗失数量统计。
4. 支持借阅中、已归还、逾期记录统计。
5. 支持未缴罚款数量和金额统计。
6. 支持按分类统计图书数量。
7. 支持按时间范围查询借阅记录。
8. 支持读者查询本人借阅历史。
9. 管理端可查看全局统计，读者端仅可查看个人数据。

### 6.11 系统基础配置

系统应支持维护基础业务参数。

功能要求：

1. 支持配置默认借阅天数。
2. 支持配置默认最大借阅数量。
3. 支持配置逾期每日罚款金额。
4. 系统配置变更后应影响后续业务处理。
5. 已产生的历史借阅记录不因配置变更自动修改。

## 7. 业务流程

### 7.1 用户登录流程

1. 用户进入登录页面。
2. 用户输入用户名和密码。
3. 系统校验输入项。
4. 系统校验用户状态和密码。
5. 校验通过后生成登录凭证。
6. 系统根据用户角色展示对应功能。
7. 校验失败时提示登录失败。

### 7.2 图书入库流程

1. 图书管理员录入图书资料。
2. 系统校验 ISBN、分类和必填项。
3. 图书管理员录入馆藏副本数量、馆藏编号和存放位置。
4. 系统保存图书资料。
5. 系统保存馆藏副本。
6. 图书进入可查询和可借阅状态。

### 7.3 图书借阅流程

1. 读者或管理员查询目标图书。
2. 系统展示图书详情和可借数量。
3. 发起借阅操作。
4. 系统校验读者状态、借阅数量、图书状态和副本状态。
5. 校验通过后生成借阅记录。
6. 系统将馆藏副本状态更新为借出。
7. 系统返回借阅成功信息和应还时间。

### 7.4 图书归还流程

1. 管理员查询待归还记录。
2. 管理员选择借阅记录并办理归还。
3. 系统校验记录状态。
4. 系统记录归还时间。
5. 系统判断是否逾期。
6. 系统更新借阅状态。
7. 系统更新馆藏副本状态。
8. 如产生罚款，系统生成或更新罚款记录。

### 7.5 逾期处理流程

1. 系统根据应还时间识别逾期记录。
2. 管理员查看逾期清单。
3. 读者归还图书后，系统计算或记录罚款信息。
4. 管理员维护罚款缴纳或免除状态。
5. 读者查看本人逾期和罚款处理结果。

## 8. 数据需求

系统应管理以下核心数据：

1. 用户数据：用户编号、用户名、密码、真实姓名、手机号、邮箱、头像、读者编号、最大可借数量、用户状态等。
2. 角色数据：角色名称、角色编码、角色描述、角色状态等。
3. 权限数据：权限名称、权限编码、权限类型、访问路径、状态等。
4. 图书分类数据：分类名称、分类编码、父分类、排序号、描述、状态等。
5. 图书资料数据：ISBN、书名、作者、出版社、出版日期、分类、封面、简介、价格、页数、状态等。
6. 馆藏副本数据：馆藏编号、所属图书、存放位置、副本状态、入库时间等。
7. 借阅记录数据：借阅编号、读者、图书、馆藏副本、借阅时间、应还时间、归还时间、借阅状态、办理人等。
8. 罚款记录数据：借阅记录、读者、罚款类型、罚款金额、逾期天数、缴纳状态、处理人等。
9. 系统配置数据：配置键、配置值、配置名称、配置状态等。

## 9. 非功能需求

### 9.1 性能需求

1. 普通查询在正常数据量下响应时间应不超过 3 秒。
2. 登录、借阅、归还等核心操作在正常环境下响应时间应不超过 5 秒。
3. 列表查询必须支持分页。
4. 高频查询条件应支持索引优化。
5. 统计查询应避免影响核心借阅和归还操作。

### 9.2 安全需求

1. 密码必须加密存储。
2. 受保护功能必须校验登录状态。
3. 管理端功能必须校验角色权限。
4. 普通读者只能访问本人数据。
5. 系统应对关键输入参数进行合法性校验。
6. 系统异常不得向前端暴露敏感堆栈信息。

### 9.3 可靠性需求

1. 借阅和归还操作必须保证借阅记录和馆藏副本状态一致。
2. 重复提交不得造成重复借阅、重复归还或副本状态错误。
3. 数据保存失败时应返回明确错误信息。
4. 关键业务数据应保留创建时间和更新时间。

### 9.4 易用性需求

1. 管理端功能应按业务模块组织。
2. 高频操作应入口清晰，如新增图书、入库副本、办理借阅、办理归还。
3. 查询条件应符合图书管理员和读者的常用操作习惯。
4. 表单应提供必填校验和格式校验。
5. 操作成功或失败后应有明确反馈。

### 9.5 可维护性需求

1. 系统功能应按模块边界组织。
2. 用户、图书、馆藏、借阅、罚款等核心对象应边界清晰。
3. 公共响应、异常处理、权限校验和参数校验应统一。
4. 系统配置应集中管理。

## 10. 权限要求

1. 未登录用户只能访问登录功能和允许公开的图书查询能力。
2. 普通读者只能查看图书公开信息、本人资料、本人借阅记录和本人罚款记录。
3. 图书管理员可维护图书分类、图书资料、馆藏副本、借阅、归还、逾期罚款和统计数据。
4. 超级管理员可维护用户、角色、权限、系统配置和全局业务数据。
5. 禁用用户、禁用角色和禁用权限不得继续访问受保护功能。

## 11. 验收标准

系统满足以下条件时，可认为 V1.0 需求达到验收要求：

1. 用户可通过正确账号密码登录系统。
2. 错误账号、错误密码、禁用账号无法登录系统。
3. 超级管理员可维护用户、角色和权限。
4. 图书管理员可维护图书分类。
5. 图书管理员可维护图书资料。
6. 图书管理员可维护馆藏副本和存放位置。
7. 系统可准确统计图书可借数量和借出数量。
8. 系统可完成借阅登记，并将副本状态更新为借出。
9. 系统可完成归还登记，并按归还结果更新副本状态。
10. 系统可识别逾期记录并生成或维护罚款记录。
11. 读者可查询图书资料和可借状态。
12. 读者只能查看本人借阅记录和罚款记录。
13. 管理端可查询全局借阅、逾期、罚款和库存统计数据。
14. 系统可对必填、唯一性、状态、数量和权限等关键规则进行校验。
15. 系统异常和业务失败应返回明确提示，不影响主要业务流程。

## 12. 后续扩展方向

系统后续版本可扩展以下功能：

1. 图书预约。
2. 图书续借。
3. 到期提醒。
4. 在线缴纳罚款。
5. 操作日志审计。
6. 图书采购管理。
7. 多馆区调拨。
8. 数据报表和可视化分析。
9. 移动端适配。
