## 2. 设计目标

系统概要设计目标如下：

1. 建立清晰的系统分层结构，便于后续开发和维护。
2. 将需求中的业务模块映射为可实现的后端模块和数据模型。
3. 保证用户、角色、图书、库存、借阅、归还、逾期等核心业务形成完整闭环。
4. 通过统一认证、统一响应、统一异常处理提升系统一致性。
5. 支持管理端和读者端按角色访问不同功能。
6. 为后续接口设计、数据库设计和详细设计提供稳定边界。

## 3. 设计原则

### 3.1 分层清晰

系统采用表现层、接口层、业务层、数据访问层和数据存储层的分层设计。各层职责独立，上一层通过明确接口调用下一层，避免业务逻辑散落在控制器或数据访问代码中。

### 3.2 模块内聚

系统按业务能力划分模块，包括登录认证、用户角色、图书分类、图书信息、库存、借阅归还、逾期罚款和统计查询。每个模块围绕自己的核心数据和业务规则组织。

### 3.3 数据一致

借阅和归还操作会同时影响借阅记录和库存数据，因此应在业务层统一处理，并通过事务保证库存数量、借阅状态和归还时间保持一致。

### 3.4 安全可控

系统通过登录令牌识别用户身份，通过角色控制访问范围。普通读者只能访问本人数据，管理员可访问管理范围内的数据，超级管理员拥有全局管理能力。

### 3.5 可扩展

V1.0 聚焦核心借阅闭环，模块和数据结构预留预约、续借、借阅规则配置、操作日志和统计报表等后续扩展能力。

## 4. 总体架构设计

### 4.1 架构模式

系统采用前后端分离的 Web 应用架构。前端分为管理端和读者端，后端提供统一 HTTP/JSON 接口，数据持久化到 MySQL，登录状态和部分缓存能力可由 Redis 支撑。

```text
用户浏览器
  |
  | HTTP/JSON
  v
前端应用
  |-- 管理端：用户、角色、图书、库存、借阅、统计
  |-- 读者端：图书查询、我的借阅、个人资料
  |
  | HTTP/JSON + Token
  v
后端服务 Spring Boot
  |-- Controller 接口层
  |-- Service 业务层
  |-- Mapper 数据访问层
  |-- Common 公共能力
  |
  +--> MySQL：业务数据持久化
  +--> Redis：登录状态、缓存或临时数据
```

### 4.2 技术架构

| 层级 | 技术或组件 | 说明 |
| --- | --- | --- |
| 前端层 | Web 管理端、Web 读者端 | 通过浏览器访问系统功能 |
| 接口层 | Spring MVC Controller | 接收请求、参数校验、返回统一结果 |
| 业务层 | Spring Service | 实现核心业务规则和事务控制 |
| 数据访问层 | MyBatis-Plus Mapper | 访问 MySQL 数据表 |
| 数据层 | MySQL 8.x | 存储用户、角色、图书、库存、借阅等数据 |
| 缓存层 | Redis | 支持令牌状态、缓存或临时数据 |
| 安全能力 | JWT、BCrypt | 登录凭证生成和密码加密 |
| 构建工具 | Maven | 项目构建和依赖管理 |
| 运行环境 | Java 8、Spring Boot 2.7.x | 后端运行基础 |

### 4.3 部署架构

V1.0 可采用单机部署方式，适合课程设计、中小型图书室和演示环境。

```text
客户端浏览器
  |
  v
Web 前端服务
  |
  v
Spring Boot 后端服务
  |-- MySQL 数据库
  |-- Redis 服务
```

在开发或课程设计环境中，前端和后端可以分别启动；在部署环境中，前端静态资源可由独立 Web 服务托管，也可由后端服务统一托管。

## 5. 系统模块设计

### 5.1 模块总览

| 模块 | 主要职责 | 使用角色 |
| --- | --- | --- |
| 登录认证模块 | 登录、令牌生成、身份识别 | 全部用户 |
| 用户管理模块 | 用户新增、查询、修改、禁用、删除 | 超级管理员 |
| 角色权限模块 | 角色维护、用户角色绑定、访问控制 | 超级管理员 |
| 图书分类模块 | 分类新增、修改、查询、禁用、删除 | 超级管理员、图书管理员 |
| 图书信息模块 | 图书新增、修改、查询、详情、上下架、删除 | 超级管理员、图书管理员、普通读者 |
| 库存管理模块 | 库存设置、调整、查询和业务联动 | 超级管理员、图书管理员 |
| 借阅管理模块 | 借阅办理、借阅校验、借阅记录查询 | 超级管理员、图书管理员、普通读者 |
| 归还管理模块 | 归还办理、逾期判断、库存恢复 | 超级管理员、图书管理员 |
| 逾期罚款模块 | 逾期识别、罚款金额和缴纳状态维护 | 超级管理员、图书管理员、普通读者 |
| 统计查询模块 | 图书、库存、借阅和逾期统计 | 超级管理员、图书管理员 |
| 公共支撑模块 | 统一响应、异常处理、参数校验、自动填充 | 后端内部 |

### 5.2 登录认证模块

登录认证模块负责用户登录和访问身份识别。

主要设计：

1. 用户提交用户名和密码。
2. 系统根据用户名查询用户信息。
3. 系统使用 BCrypt 校验密码。
4. 校验通过后生成 JWT 登录令牌。
5. 后续请求通过令牌识别当前用户。
6. 对禁用用户、无效令牌和过期令牌进行拦截。

当前项目中已有 `LoginController`、`LoginService`、`LoginServiceImpl`、`LoginDto` 和 JWT 密钥配置，可在此基础上补充令牌拦截器、过期时间和用户状态校验。

### 5.3 用户管理模块

用户管理模块负责维护系统账号和人员基础资料。

主要设计：

1. 通过用户表保存用户名、密码、真实姓名、手机号、邮箱、头像和状态。
2. 新增用户时对密码进行加密。
3. 查询用户时支持按编号、用户名、真实姓名、手机号和状态筛选。
4. 删除用户采用逻辑删除。
5. 用户状态用于控制登录和借阅资格。

当前项目中已有 `SysUser`、`SysUserController`、`SysUserService`、`SysUserMapper`，后续需补充分页查询、修改、禁用、删除和角色绑定能力。

### 5.4 角色权限模块

角色权限模块负责维护用户访问范围。

主要设计：

1. 通过角色表保存角色名称、角色编码、描述和状态。
2. 通过用户角色关联表维护用户与角色关系。
3. 系统默认角色包括超级管理员和普通用户，后续可增加图书管理员角色。
4. 接口访问时根据当前用户角色判断是否允许访问。
5. 角色禁用后不参与权限判断。

当前项目中已有 `SysRole` 和 `SysUserRole` 实体，后续需补充角色 Mapper、Service、Controller 以及权限校验组件。

### 5.5 图书分类模块

图书分类模块负责维护图书分类体系。

主要设计：

1. 分类支持父子结构，顶级分类的 `parentId` 为 0。
2. 分类编码和分类名称保持唯一。
3. 分类状态控制是否允许继续绑定新图书。
4. 删除分类时应校验是否已被图书使用。
5. 分类列表可按排序号展示。

当前项目中已有 `BookCategory` 实体，后续需补充分类控制器、服务和数据访问对象。

### 5.6 图书信息模块

图书信息模块负责图书基础资料维护和读者查询。

主要设计：

1. 图书表保存书名、ISBN、作者、出版社、出版日期、分类、封面、简介、价格、页数和状态。
2. ISBN 作为业务唯一标识。
3. 管理端支持新增、修改、上下架、删除和详情查询。
4. 读者端仅查询上架图书。
5. 删除图书前应检查是否存在未归还借阅记录。

当前项目中已有 `Book` 实体，后续需补充图书控制器、服务、Mapper、查询 DTO 和返回 VO。

### 5.7 库存管理模块

库存管理模块负责维护每本图书的数量和位置。

主要设计：

1. 每本图书对应一条库存记录。
2. 库存包含总数量、可借数量、已借数量和存放位置。
3. 管理员可调整库存总量和存放位置。
4. 借阅成功时扣减可借数量，增加已借数量。
5. 归还成功时增加可借数量，减少已借数量。
6. 库存更新需要与借阅和归还操作保持事务一致。

当前项目中已有 `BookStock` 实体，后续需补充库存控制器、服务、Mapper，并在借阅归还业务中调用库存变更逻辑。

### 5.8 借阅管理模块

借阅管理模块负责记录图书借出过程。

主要设计：

1. 借阅记录关联用户和图书。
2. 借阅前校验用户状态、图书状态、库存数量和重复借阅规则。
3. 借阅成功后生成借阅记录，状态为借阅中。
4. 借阅成功后同步更新库存。
5. 管理端可查询全部借阅记录，读者端只能查询本人记录。

当前项目中已有 `BookBorrow` 实体，后续需补充借阅服务，并将借阅记录创建和库存扣减放在同一事务中。

### 5.9 归还管理模块

归还管理模块负责处理图书归还。

主要设计：

1. 归还时根据借阅记录编号查询借阅中记录。
2. 已归还记录不允许重复归还。
3. 归还成功后记录归还时间。
4. 系统比较归还时间和应还时间，判断是否逾期。
5. 归还成功后同步恢复库存。
6. 如产生逾期，记录罚款金额和罚款状态。

归还业务应与库存恢复、借阅状态更新处于同一事务边界内。

### 5.10 逾期罚款模块

逾期罚款模块负责识别逾期记录和维护罚款状态。

主要设计：

1. 超过应还时间且未归还的记录可视为逾期。
2. 归还时如果超过应还时间，系统标记逾期或记录罚款信息。
3. 罚款状态包括未缴纳和已缴纳。
4. 管理员可维护罚款金额和缴纳状态。
5. 读者只能查看本人逾期和罚款信息。

V1.0 仅实现基础逾期和罚款记录，不接入在线支付。

### 5.11 统计查询模块

统计查询模块负责展示基础运行数据。

主要设计：

1. 图书总数统计。
2. 可借数量统计。
3. 已借数量统计。
4. 借阅中记录统计。
5. 已归还记录统计。
6. 逾期记录统计。
7. 按分类统计图书数量。

统计数据主要供管理端工作台和统计页面使用，普通读者不展示全局统计。

### 5.12 公共支撑模块

公共支撑模块为业务模块提供通用能力。

主要设计：

1. 统一响应结构。
2. 全局异常处理。
3. 业务异常封装。
4. 参数校验。
5. 自动填充创建时间和更新时间。
6. 逻辑删除配置。
7. Redis 工具能力。

当前项目已有 `Result`、`BusinessException`、`GlobalExceptionHandler`、`MyMetaObjectHandler`、`MybatisPlusConfig`、`RedisUtil` 等公共类，可继续复用。

## 6. 后端分层设计

### 6.1 分层结构

后端采用典型 Spring Boot 分层结构。

```text
com.book
  |-- controller      接口控制层
  |-- service         业务接口层
  |-- service.impl    业务实现层
  |-- mapper          数据访问层
  |-- domain
  |    |-- entity     数据库实体
  |    |-- dto        请求参数对象
  |    |-- vo         响应视图对象
  |-- common          公共响应、异常、工具类
  |-- config          系统配置
```

### 6.2 Controller 层

Controller 层负责：

1. 定义 HTTP 接口路径。
2. 接收请求参数。
3. 触发参数校验。
4. 调用 Service 层。
5. 返回统一响应结果。

Controller 层不应直接编写复杂业务规则，不应直接操作 Mapper。

### 6.3 Service 层

Service 层负责：

1. 处理核心业务规则。
2. 编排多个数据对象的操作。
3. 控制事务边界。
4. 处理权限相关业务判断。
5. 抛出业务异常。

借阅、归还、库存调整等会修改多张表的操作应在 Service 层使用事务。

### 6.4 Mapper 层

Mapper 层负责：

1. 封装数据库访问。
2. 提供基础增删改查能力。
3. 支持复杂查询或统计 SQL。

V1.0 可优先使用 MyBatis-Plus 提供的基础能力，复杂统计查询再补充自定义 SQL。

### 6.5 Entity、DTO、VO

实体和传输对象设计如下：

1. Entity：对应数据库表结构，例如 `SysUser`、`Book`、`BookStock`。
2. DTO：用于接收请求参数，例如登录参数、图书查询条件、借阅请求。
3. VO：用于返回前端展示数据，例如图书详情、借阅记录详情、统计结果。

不建议直接把包含敏感字段的 Entity 返回给前端，例如用户密码字段应在响应中隐藏。

## 7. 数据架构设计

### 7.1 核心数据表

| 数据表 | 实体 | 主要用途 |
| --- | --- | --- |
| `sys_user` | `SysUser` | 保存系统用户和读者信息 |
| `sys_role` | `SysRole` | 保存角色信息 |
| `sys_user_role` | `SysUserRole` | 保存用户角色关系 |
| `book_category` | `BookCategory` | 保存图书分类 |
| `book` | `Book` | 保存图书基础信息 |
| `book_stock` | `BookStock` | 保存图书库存 |
| `book_borrow` | `BookBorrow` | 保存借阅和归还记录 |

### 7.2 数据关系

核心关系如下：

1. 一个用户可绑定多个角色。
2. 一个角色可绑定多个用户。
3. 一个分类可包含多本图书。
4. 一本图书对应一条库存记录。
5. 一本图书可产生多条借阅记录。
6. 一个用户可产生多条借阅记录。

```text
sys_user      sys_user_role      sys_role
   1  <------      N      ------>   1

book_category 1  --------  N book
book          1  --------  1 book_stock
book          1  --------  N book_borrow
sys_user      1  --------  N book_borrow
```

### 7.3 逻辑删除

用户、角色、分类、图书等基础数据应采用逻辑删除，避免影响历史借阅记录。借阅记录作为业务流水数据，原则上不进行物理删除。

### 7.4 状态值设计

概要状态值如下：

| 对象 | 字段 | 状态说明 |
| --- | --- | --- |
| 用户 | `status` | 0 禁用，1 正常 |
| 角色 | `status` | 0 禁用，1 正常 |
| 分类 | `status` | 0 禁用，1 正常 |
| 图书 | `status` | 0 下架，1 上架 |
| 借阅 | `status` | 0 借阅中，1 已归还，2 逾期 |
| 罚款 | `fine_status` | 0 未缴纳，1 已缴纳 |

### 7.5 数据一致性设计

系统关键一致性要求如下：

1. 新增图书后应创建或维护库存记录。
2. 借阅成功后必须同时创建借阅记录并更新库存。
3. 归还成功后必须同时更新借阅记录并恢复库存。
4. 库存数量不得为负。
5. 可借数量与已借数量之和不得大于总数量。
6. 删除或下架图书前应校验未归还借阅记录。

## 8. 核心业务流程设计

### 8.1 登录流程

```text
用户提交用户名和密码
  -> Controller 接收登录请求
  -> Service 查询用户
  -> 校验用户状态
  -> BCrypt 校验密码
  -> 生成 JWT
  -> 返回统一响应
```

异常情况：

1. 用户不存在：返回登录失败。
2. 密码错误：返回登录失败。
3. 用户禁用：返回账号不可用。
4. 系统异常：返回统一异常响应。

### 8.2 图书入库流程

```text
管理员提交图书信息和库存信息
  -> 校验必填字段
  -> 校验 ISBN 唯一
  -> 校验分类有效
  -> 保存图书信息
  -> 保存库存信息
  -> 返回入库成功
```

设计要点：

1. 图书信息与库存信息可在同一业务流程中保存。
2. ISBN 唯一性冲突时抛出业务异常。
3. 库存数量应进行非负校验。

### 8.3 借阅流程

```text
管理员或读者发起借阅
  -> 校验用户是否正常
  -> 校验图书是否上架
  -> 校验库存是否可借
  -> 校验是否存在重复未归还记录
  -> 创建借阅记录
  -> 更新库存数量
  -> 返回借阅成功
```

设计要点：

1. 借阅记录创建和库存扣减必须在同一事务中完成。
2. 并发借阅同一本书时，应防止库存超扣。
3. 借阅成功后状态为借阅中。

### 8.4 归还流程

```text
管理员发起归还
  -> 查询借阅记录
  -> 校验记录是否借阅中
  -> 设置归还时间
  -> 判断是否逾期
  -> 更新借阅状态和罚款信息
  -> 恢复库存数量
  -> 返回归还成功
```

设计要点：

1. 已归还记录不能重复归还。
2. 归还记录更新和库存恢复必须在同一事务中完成。
3. 逾期罚款规则可在 V1.0 先采用基础记录方式，后续再扩展计算规则。

### 8.5 逾期处理流程

```text
系统查询未归还记录
  -> 当前时间超过应还时间
  -> 标记或展示为逾期
  -> 管理员维护罚款金额
  -> 管理员维护缴纳状态
  -> 读者查看本人处理结果
```

设计要点：

1. 逾期可以通过实时查询判断，也可以通过定时任务更新状态。
2. V1.0 可优先采用实时查询判断，降低实现复杂度。

## 9. 接口概要设计

### 9.1 接口风格

系统接口采用 REST 风格设计，数据格式采用 JSON。

统一响应结构建议如下：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

当前项目已有 `Result` 公共响应类，后续接口应统一返回该结构或保持兼容结构。

### 9.2 接口分组

| 接口分组 | 路径建议 | 说明 |
| --- | --- | --- |
| 登录认证 | `/login`、`/logout` | 登录、退出、身份校验 |
| 用户管理 | `/user` | 用户新增、查询、修改、禁用、删除 |
| 角色管理 | `/role` | 角色维护和用户角色绑定 |
| 图书分类 | `/category` | 分类维护 |
| 图书信息 | `/book` | 图书维护和查询 |
| 库存管理 | `/stock` | 库存查询和调整 |
| 借阅管理 | `/borrow` | 借阅办理和记录查询 |
| 归还管理 | `/return` | 归还办理 |
| 逾期罚款 | `/fine`、`/overdue` | 逾期查询和罚款维护 |
| 统计查询 | `/statistics` | 管理端工作台和统计数据 |

### 9.3 接口权限

接口权限按角色控制：

1. 登录接口允许未登录访问。
2. 图书公开查询接口可面向普通读者开放。
3. 用户、角色管理接口仅超级管理员访问。
4. 图书、分类、库存、借阅、归还接口由超级管理员和图书管理员访问。
5. 个人借阅接口允许普通读者访问，但只能访问本人数据。

## 10. 权限设计

### 10.1 权限模型

系统采用基于角色的访问控制模型。

```text
用户 -> 用户角色关联 -> 角色 -> 功能权限
```

V1.0 可先采用角色编码控制接口访问，后续再扩展独立权限表和菜单权限表。

### 10.2 角色设计

| 角色 | 角色编码 | 权限范围 |
| --- | --- | --- |
| 超级管理员 | `admin` | 用户、角色、图书、库存、借阅、统计等全部功能 |
| 图书管理员 | `librarian` | 图书、分类、库存、借阅、归还、逾期和统计功能 |
| 普通读者 | `user` | 图书查询、个人资料、本人借阅和本人罚款信息 |

当前初始化 SQL 中已有 `admin` 和 `user`，建议补充 `librarian` 角色以匹配 PRD 中的图书管理员场景。

### 10.3 数据权限

数据权限规则如下：

1. 超级管理员可查看全部数据。
2. 图书管理员可查看图书和借阅业务数据。
3. 普通读者只能查看本人资料、本人借阅记录和本人罚款记录。
4. 查询个人数据时，应以后端解析出的当前登录用户编号为准，不应完全信任前端传入的用户编号。

## 11. 异常处理设计

### 11.1 异常分类

| 异常类型 | 说明 | 示例 |
| --- | --- | --- |
| 参数异常 | 请求参数为空或格式错误 | 用户名为空、库存数量为负 |
| 认证异常 | 未登录、令牌无效、令牌过期 | Token 缺失 |
| 权限异常 | 当前用户无权访问功能或数据 | 普通读者访问用户管理 |
| 业务异常 | 不满足业务规则 | 库存不足、图书下架 |
| 系统异常 | 数据库、缓存或未知程序错误 | 数据库连接异常 |

### 11.2 处理方式

1. Controller 层参数校验失败时返回明确提示。
2. Service 层业务规则失败时抛出业务异常。
3. 全局异常处理器捕获异常并转为统一响应。
4. 系统异常不直接暴露堆栈信息给前端。
5. 关键异常应记录日志，便于排查。

当前项目已有 `BusinessException` 和 `GlobalExceptionHandler`，后续应扩展认证异常、权限异常和参数校验异常的统一处理。

## 12. 安全设计

### 12.1 密码安全

1. 用户密码采用 BCrypt 加密存储。
2. 新增和重置密码时统一走密码加密逻辑。
3. 查询用户信息时不向前端返回密码字段。

### 12.2 登录令牌

1. 登录成功后生成 JWT。
2. JWT 中可包含用户编号和必要角色信息。
3. JWT 密钥从配置读取，不应在生产环境使用默认值。
4. 后续可结合 Redis 管理令牌有效期和退出登录状态。

### 12.3 接口安全

1. 受保护接口必须校验登录状态。
2. 管理接口必须校验角色权限。
3. 普通读者访问个人数据时必须校验数据归属。
4. 所有关键参数应进行合法性校验。

## 13. 事务设计

需要事务控制的核心场景包括：

1. 新增图书并初始化库存。
2. 借阅图书并扣减库存。
3. 归还图书并恢复库存。
4. 删除图书并校验未归还记录。
5. 用户角色绑定变更。

事务失败时，应整体回滚，避免出现借阅记录已生成但库存未扣减、归还状态已更新但库存未恢复等数据不一致问题。

## 14. 缓存与 Redis 设计

Redis 在 V1.0 中主要作为可选支撑能力使用。

可使用场景：

1. 登录令牌状态缓存。
2. 用户权限信息缓存。
3. 高频分类数据缓存。
4. 短期统计结果缓存。

V1.0 可优先保证数据库业务正确性，缓存用于优化读取性能，不应让缓存成为核心业务数据的唯一来源。

## 15. 日志设计

系统应具备基础日志能力。

建议记录内容：

1. 用户登录成功和失败。
2. 新增、修改、删除图书。
3. 库存调整。
4. 借阅办理。
5. 归还办理。
6. 逾期和罚款状态变更。
7. 系统异常。

V1.0 可先使用应用日志记录，后续版本可扩展独立操作日志表。

## 19. 概要设计结论

明月图书借阅管理系统 V1.0 采用前后端分离、Spring Boot 单体后端、MySQL 持久化、Redis 辅助缓存的总体架构。系统按登录认证、用户角色、图书分类、图书信息、库存、借阅归还、逾期罚款和统计查询划分模块，以用户、角色、图书、库存和借阅记录为核心数据对象，通过统一响应、统一异常、事务控制和角色权限保证系统的可维护性、数据一致性和安全性。

该概要设计与当前代码工程保持一致，可直接作为后续数据库设计、接口设计和详细设计的基础。
