# 明月图书借阅管理系统 V1.0 数据库设计说明书

## 1. 文档概述

### 1.1 文档目的

本文档基于《明月图书借阅管理系统 V1.0 PRD 产品需求文档》和《明月图书借阅管理系统 V1.0 系统概要设计说明书》重新设计数据库模型，用于支撑系统 V1.0 的完整产品需求和概要设计目标。

本设计以业务需求为主导，不以既有 SQL 草稿或当前实体类为表结构约束。后续编码时，应以本文档作为数据库和实体模型调整依据。

### 1.2 设计范围

数据库设计覆盖以下业务能力：

1. 登录认证。
2. 用户管理。
3. 角色权限管理。
4. 图书分类管理。
5. 图书资料管理。
6. 馆藏副本和库存管理。
7. 图书借阅管理。
8. 图书归还管理。
9. 逾期和罚款管理。
10. 基础统计查询。

## 2. 数据库设计原则

### 2.1 满足产品闭环

数据库必须支持从图书入库、图书查询、读者借阅、图书归还、逾期识别、罚款记录到统计查询的完整业务闭环。

### 2.2 区分书目和馆藏

一本书的书目信息和实际馆藏副本不是同一概念。书目信息表示“这是什么书”，馆藏副本表示“这本书有哪几册可以借”。因此数据库将图书资料和图书副本分开设计：

1. `book_info` 保存 ISBN、书名、作者、出版社等书目资料。
2. `book_copy` 保存馆藏条码、存放位置、可借状态等单册信息。

这样可以更准确地支持库存统计、借阅归还、图书损坏、遗失和下架等业务。

### 2.3 借阅记录关联具体副本

借阅记录应关联到具体的图书副本，而不是只关联书目信息。这样可以明确读者借走的是哪一册书，也便于归还时准确恢复该副本状态。

### 2.4 权限模型可扩展

V1.0 明确存在超级管理员、图书管理员、普通读者三类角色。数据库采用用户、角色、权限三层模型，支持当前角色权限控制，也便于后续扩展菜单权限和按钮权限。

### 2.5 历史数据可追溯

借阅记录、罚款记录等业务流水数据不做物理删除，保证后续统计、审计和问题追溯。

## 5. 表结构设计

### 5.1 用户表 `sys_user`

#### 5.1.1 表说明

存储系统用户信息，包括超级管理员、图书管理员和普通读者。用户表同时服务登录认证、用户资料、读者借阅归属和数据权限判断。

#### 5.1.2 字段设计

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | 是 | 自增 | 用户 ID |
| `username` | VARCHAR(50) | 是 | 无 | 登录用户名 |
| `password` | VARCHAR(100) | 是 | 无 | BCrypt 加密密码 |
| `real_name` | VARCHAR(50) | 是 | 无 | 真实姓名 |
| `phone` | VARCHAR(20) | 否 | NULL | 手机号 |
| `email` | VARCHAR(100) | 否 | NULL | 邮箱 |
| `avatar` | VARCHAR(255) | 否 | NULL | 头像地址 |
| `reader_no` | VARCHAR(50) | 否 | NULL | 读者编号，普通读者可用 |
| `max_borrow_count` | INT | 是 | 5 | 最大可借数量 |
| `status` | TINYINT | 是 | 1 | 用户状态：0 禁用，1 正常 |
| `last_login_time` | DATETIME | 否 | NULL | 最近登录时间 |
| `create_time` | DATETIME | 是 | 当前时间 | 创建时间 |
| `update_time` | DATETIME | 是 | 当前时间 | 更新时间 |
| `is_deleted` | TINYINT | 是 | 0 | 逻辑删除：0 未删除，1 已删除 |

#### 5.1.3 约束与索引

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `id` | 唯一标识用户 |
| 唯一索引 | `username` | 登录账号唯一 |
| 唯一索引 | `reader_no` | 读者编号唯一 |
| 唯一索引 | `phone` | 手机号唯一 |
| 唯一索引 | `email` | 邮箱唯一 |
| 普通索引 | `status`、`is_deleted` | 用户筛选 |

#### 5.1.4 业务规则

1. 密码必须加密存储。
2. 禁用用户不能登录，不能新增借阅。
3. 普通读者只能查看自己的个人资料和借阅记录。
4. `max_borrow_count` 用于控制读者最大借阅数量。

### 5.2 角色表 `sys_role`

#### 5.2.1 表说明

存储系统角色。V1.0 角色包括超级管理员、图书管理员、普通读者。

#### 5.2.2 字段设计

| 字段名 | 类型 | 必填 | 默认值 | 说明 |

| `description` | VARCHAR(255) | 否 | NULL | 角色描述 |
| `status` | TINYINT | 是 | 1 | 状态：0 禁用，1 正常 |
| `create_time` | DATETIME | 是 | 当前时间 | 创建时间 |
| `update_time` | DATETIME | 是 | 当前时间 | 更新时间 |
| `is_deleted` | TINYINT | 是 | 0 | 逻辑删除 |

#### 5.2.3 约束与索引

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `id` | 唯一标识角色 |
| 唯一索引 | `role_code` | 角色编码唯一 |
| 唯一索引 | `role_name` | 角色名称唯一 |
| 普通索引 | `status`、`is_deleted` | 角色筛选 |

#### 5.2.4 业务规则

1. `admin` 拥有全部权限。

3. `reader` 只能访问图书查询、个人资料、本人借阅和本人罚款。
4. 禁用角色不参与权限判断。

### 5.8 图书馆藏副本表 `book_copy`

#### 5.8.1 表说明

存储每一本实际馆藏副本。库存总数、可借数量、已借数量由该表按状态统计得到。

#### 5.8.2 字段设计

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | 是 | 自增 | 馆藏副本 ID |
| `book_id` | BIGINT | 是 | 无 | 图书资料 ID |
| `copy_code` | VARCHAR(50) | 是 | 无 | 馆藏条码或副本编号 |
| `location` | VARCHAR(100) | 否 | NULL | 存放位置 |
| `status` | TINYINT | 是 | 1 | 副本状态：0 下架，1 可借，2 借出，3 损坏，4 遗失 |
| `in_time` | DATETIME | 是 | 当前时间 | 入库时间 |
| `remark` | VARCHAR(255) | 否 | NULL | 备注 |
| `create_time` | DATETIME | 是 | 当前时间 | 创建时间 |
| `update_time` | DATETIME | 是 | 当前时间 | 更新时间 |
| `is_deleted` | TINYINT | 是 | 0 | 逻辑删除 |

#### 5.8.3 约束与索引

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `id` | 唯一标识馆藏副本 |
| 唯一索引 | `copy_code` | 馆藏条码唯一 |
| 普通索引 | `book_id` | 查询某图书的副本 |
| 普通索引 | `status` | 库存状态统计 |
| 普通索引 | `location` | 按位置查询 |
| 组合索引 | `book_id`、`status`、`is_deleted` | 统计某图书可借、借出、下架数量 |

#### 5.8.4 业务规则

1. 新增库存时实际新增 `book_copy` 记录。
2. 图书借出后，副本状态由可借变为借出。
3. 图书归还后，副本状态由借出变为可借。
4. 损坏、遗失、下架副本不允许借出。
5. 统计库存时按 `book_id` 聚合副本状态。

#### 5.9.4 业务规则

## 6. 库存统计设计

### 6.1 统计口径

库存不单独维护汇总表，而是由 `book_copy` 按状态实时统计。

| 指标 | 统计方式 |
| --- | --- |
| 总数量 | `book_copy` 中同一 `book_id` 且 `is_deleted = 0` 的数量 |
| 可借数量 | `book_copy.status = 1` 的数量 |
| 已借数量 | `book_copy.status = 2` 的数量 |
| 下架数量 | `book_copy.status = 0` 的数量 |
| 损坏数量 | `book_copy.status = 3` 的数量 |
| 遗失数量 | `book_copy.status = 4` 的数量 |

### 6.2 设计理由

1. 借阅和归还可以直接修改单册状态，避免汇总库存被重复扣减。
2. 管理员能定位具体哪一册书被借出、损坏或遗失。
3. 统计总库存和可借库存时更准确。
4. 后续扩展多馆区、书架位置、条码扫描时更自然。

## 8. 关键业务数据流

### 8.1 图书入库

1. 管理员创建 `book_info`。
2. 系统校验 ISBN 唯一、分类有效。
3. 管理员根据实际数量创建多条 `book_copy`。
4. 每条 `book_copy` 生成唯一 `copy_code`。
5. 副本初始状态为可借。

### 8.2 图书借阅

1. 系统校验用户状态正常。
2. 系统校验用户当前借阅数量未超过限制。
3. 系统校验 `book_info.status = 1`。
4. 系统选择或指定一条 `book_copy.status = 1` 的副本。
5. 创建 `borrow_record`。
6. 将 `book_copy.status` 更新为借出。

以上步骤必须在同一事务中完成。

### 8.3 图书归还

1. 管理员查询 `borrow_record`。
2. 系统校验记录处于借阅中或逾期状态。
3. 写入 `return_time`。
4. 判断是否超过 `due_time`。
5. 更新 `borrow_record.status`。
6. 必要时创建或更新 `fine_record`。
7. 将 `book_copy.status` 更新为可借，遗失或损坏场景除外。

以上步骤必须在同一事务中完成。

### 8.4 逾期罚款

1. 查询 `borrow_record.status = 0` 且 `due_time < 当前时间` 的记录。
2. 系统可实时展示为逾期，也可批量更新为逾期状态。
3. 归还时根据逾期天数和罚款配置计算金额。
4. 生成 `fine_record`。
5. 管理员维护罚款缴纳状态。

## 11. 数据一致性设计

### 11.1 事务边界

以下操作必须使用事务：

1. 用户角色分配。
2. 角色权限分配。
3. 图书资料新增和副本入库。
4. 借阅记录创建和副本状态变更。
5. 归还记录更新、副本状态恢复和罚款记录生成。
6. 图书删除、下架和未归还记录校验。

### 11.2 并发控制

借阅时可能出现多个用户同时借同一图书的情况。建议采用以下控制方式：

1. 查询可借副本时只选择 `book_copy.status = 1` 的记录。
2. 更新副本状态时增加条件：`status = 1`。
3. 如果更新影响行数为 0，说明副本已被借出，应提示库存不足或重新选择副本。

该方案能满足 V1.0 的并发控制要求，后续高并发场景可增加乐观锁字段。

## 16. 设计结论

本数据库设计从 PRD 和系统概要设计出发，重新建立了更贴合完整图书借阅业务的模型。核心变化是将图书资料与实际馆藏副本分离，将借阅记录关联到具体副本，并将罚款记录独立建模，同时补充了权限表、角色权限表和系统配置表。

该设计能够满足 V1.0 对用户、角色、图书分类、图书资料、库存、借阅、归还、逾期罚款和统计查询的需求，也为后续预约、续借、通知、日志和多馆区扩展保留了清晰的数据边界。
