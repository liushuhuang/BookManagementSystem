# 明月图书借阅管理系统 V1.0 数据库设计说明书

## 1. 文档概述

### 1.1 文档目的

本文档基于《明月图书借阅管理系统 V1.0 PRD 产品需求文档》和《明月图书借阅管理系统 V1.0 系统概要设计说明书》编写，用于说明系统数据库的总体设计、数据表结构、字段含义、表关系、约束规则、索引建议、状态枚举、初始化数据和数据一致性要求。

本文档为数据库建表、后端实体维护、接口开发、测试验收和软著材料整理提供依据。

### 1.2 适用范围

本文档适用于明月图书借阅管理系统 V1.0 的数据库设计阶段，覆盖用户、角色、图书分类、图书信息、库存、借阅归还、逾期罚款和基础统计所需的核心业务数据。

### 1.3 关联文档

1. `docs/需求规格说明书.md`
2. `docs/PRD产品需求文档.md`
3. `docs/系统概要设计说明书.md`
4. `图书管理系统.txt`

## 2. 数据库设计目标

数据库设计目标如下：

1. 支撑用户登录、用户管理、角色权限、图书管理、库存管理、借阅归还和逾期罚款等核心业务。
2. 保证图书、库存和借阅记录之间的数据一致性。
3. 保留历史借阅记录，满足查询、统计和追溯需要。
4. 通过主键、外键、唯一约束和业务校验降低脏数据风险。
5. 支持常用列表查询、条件查询和统计查询。
6. 与当前 Spring Boot、MyBatis-Plus、MySQL 技术栈保持一致。

## 3. 数据库环境

| 项目 | 设计值 |
| --- | --- |
| 数据库类型 | MySQL |
| 推荐版本 | MySQL 8.x |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |
| 存储引擎 | InnoDB |
| 主键策略 | BIGINT 自增主键 |
| 删除策略 | 核心基础数据采用逻辑删除 |
| 时间类型 | `DATETIME` |
| 金额类型 | `DECIMAL(10,2)` |

当前项目配置的数据库名称为 `bms`，连接信息位于 `src/main/resources/application.yml`。

## 4. 数据库命名规范

### 4.1 表命名

1. 系统用户与权限表使用 `sys_` 前缀。
2. 图书业务表使用 `book_` 前缀或 `book` 主表。
3. 表名使用小写字母和下划线。
4. 表名应表达业务含义，例如 `sys_user`、`book_borrow`。

### 4.2 字段命名

1. 字段名使用小写字母和下划线。
2. 主键统一命名为 `id`。
3. 外键字段使用业务对象名加 `_id`，例如 `user_id`、`book_id`、`category_id`。
4. 创建时间统一命名为 `create_time`。
5. 更新时间统一命名为 `update_time`。
6. 逻辑删除字段统一命名为 `is_deleted`。
7. 状态字段统一使用 `status` 或明确业务含义的状态字段，例如 `fine_status`。

### 5.3 表关系概览

```text
sys_user      sys_user_role      sys_role
   1  <------      N      ------>   1

book_category 1  --------  N book
book          1  --------  1 book_stock
book          1  --------  N book_borrow
sys_user      1  --------  N book_borrow
```

关系说明：

1. 一个用户可以绑定多个角色。
2. 一个角色可以分配给多个用户。
3. 一个分类可以包含多本图书。
4. 一本图书对应一条库存记录。
5. 一本图书可以产生多条借阅记录。
6. 一个用户可以产生多条借阅记录。

## 6. 表结构设计

### 6.1 系统用户表 `sys_user`

#### 6.1.1 表说明

`sys_user` 用于存储系统登录账号和人员基础信息，覆盖超级管理员、图书管理员和普通读者。

#### 6.1.2 字段设计

| 字段名 | 数据类型 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | 是 | 自增 | 用户 ID，主键 |
| `username` | VARCHAR(50) | 是 | 无 | 用户名，登录账号 |
| `password` | VARCHAR(100) | 是 | 无 | 加密后的密码 |
| `real_name` | VARCHAR(50) | 是 | 无 | 真实姓名 |
| `phone` | VARCHAR(20) | 否 | NULL | 手机号码 |
| `email` | VARCHAR(100) | 否 | NULL | 邮箱地址 |
| `avatar` | VARCHAR(255) | 否 | NULL | 头像 URL |
| `status` | TINYINT | 是 | 1 | 用户状态：0 禁用，1 正常 |
| `create_time` | DATETIME | 是 | 当前时间 | 创建时间 |
| `update_time` | DATETIME | 是 | 当前时间 | 更新时间 |
| `is_deleted` | TINYINT | 是 | 0 | 逻辑删除：0 未删除，1 已删除 |

#### 6.1.3 约束设计

| 约束类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `id` | 唯一标识用户 |
| 唯一约束 | `username` | 用户名不可重复 |
| 唯一约束 | `phone` | 手机号不可重复 |
| 唯一约束 | `email` | 邮箱不可重复 |
| 非空约束 | `username`、`password`、`real_name`、`status` | 保证核心信息完整 |

#### 6.1.4 索引建议

| 索引名 | 字段 | 类型 | 用途 |
| --- | --- | --- | --- |
| `uk_sys_user_username` | `username` | 唯一索引 | 登录查询 |
| `uk_sys_user_phone` | `phone` | 唯一索引 | 手机号查询和唯一校验 |
| `uk_sys_user_email` | `email` | 唯一索引 | 邮箱查询和唯一校验 |
| `idx_sys_user_status` | `status` | 普通索引 | 按状态筛选用户 |
| `idx_sys_user_deleted` | `is_deleted` | 普通索引 | 过滤逻辑删除数据 |

#### 6.1.5 业务规则

1. 密码必须加密存储，不能保存明文。
2. 禁用用户不能登录系统。
3. 禁用用户不能新增借阅。
4. 删除用户采用逻辑删除。
5. 查询用户列表时默认排除已逻辑删除数据。

#### 6.2.1 表说明

`sys_role` 用于存储系统角色信息。V1.0 建议包含超级管理员、图书管理员和普通读者三类角色。

#### 6.2.2 字段设计

| `id` | BIGINT | 是 | 自增 | 角色 ID，主键 |
| `role_name` | VARCHAR(50) | 是 | 无 | 角色名称 |
| `role_code` | VARCHAR(50) | 是 | 无 | 角色编码 |
| `description` | VARCHAR(255) | 否 | NULL | 角色描述 |
| `status` | TINYINT | 是 | 1 | 角色状态：0 禁用，1 正常 |
| `create_time` | DATETIME | 是 | 当前时间 | 创建时间 |
| `update_time` | DATETIME | 是 | 当前时间 | 更新时间 |
| `is_deleted` | TINYINT | 是 | 0 | 逻辑删除：0 未删除，1 已删除 |

#### 6.2.3 约束设计

| 约束类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `id` | 唯一标识角色 |
| 唯一约束 | `role_name` | 角色名称不可重复 |
| 唯一约束 | `role_code` | 角色编码不可重复 |
| 非空约束 | `role_name`、`role_code`、`status` | 保证角色信息完整 |

#### 6.2.4 索引建议

| 索引名 | 字段 | 类型 | 用途 |
| --- | --- | --- | --- |
| `uk_sys_role_name` | `role_name` | 唯一索引 | 角色名称唯一校验 |
| `uk_sys_role_code` | `role_code` | 唯一索引 | 权限判断和唯一校验 |
| `idx_sys_role_status` | `status` | 普通索引 | 按状态筛选角色 |
| `idx_sys_role_deleted` | `is_deleted` | 普通索引 | 过滤逻辑删除数据 |

#### 6.2.5 业务规则

1. 角色编码用于权限判断，应保持稳定。
2. 禁用角色不参与权限判断。
3. 默认角色包括 `admin`、`librarian`、`user`。
4. 当前 SQL 草稿已包含 `admin` 和 `user`，建议补充 `librarian`。

### 6.3 用户角色关联表 `sys_user_role`

#### 6.3.1 表说明

`sys_user_role` 用于维护用户和角色之间的多对多关系。

#### 6.3.2 字段设计

| 字段名 | 数据类型 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | 是 | 自增 | 关联 ID，主键 |
| `user_id` | BIGINT | 是 | 无 | 用户 ID |
| `role_id` | BIGINT | 是 | 无 | 角色 ID |
| `create_time` | DATETIME | 是 | 当前时间 | 创建时间 |

#### 6.3.3 约束设计

| 约束类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `id` | 唯一标识关联记录 |
| 唯一约束 | `user_id`、`role_id` | 同一用户不能重复绑定同一角色 |
| 外键 | `user_id` | 关联 `sys_user.id` |
| 外键 | `role_id` | 关联 `sys_role.id` |

#### 6.3.4 索引建议

| 索引名 | 字段 | 类型 | 用途 |
| --- | --- | --- | --- |
| `uk_user_role` | `user_id`、`role_id` | 唯一索引 | 防止重复绑定 |
| `idx_user_role_user_id` | `user_id` | 普通索引 | 查询用户角色 |
| `idx_user_role_role_id` | `role_id` | 普通索引 | 查询角色下用户 |

#### 6.3.5 业务规则

1. 用户至少应有一个有效角色。
2. 删除用户或角色时，应同步处理关联关系。
3. 角色绑定变更应在事务中完成。

4. 禁用分类不建议继续绑定新图书。
5. 删除分类采用逻辑删除。

5. 删除图书采用逻辑删除。
6. 普通读者默认只能查询上架且未删除图书。

### 6.6 图书库存表 `book_stock`

#### 6.6.1 表说明

`book_stock` 用于存储图书库存数量和存放位置。一本图书对应一条库存记录。

#### 6.6.2 字段设计

| 字段名 | 数据类型 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | 是 | 自增 | 库存 ID，主键 |
| `book_id` | BIGINT | 是 | 无 | 图书 ID |
| `total_quantity` | INT | 是 | 0 | 总数量 |
| `available_quantity` | INT | 是 | 0 | 可借数量 |
| `borrowed_quantity` | INT | 是 | 0 | 已借数量 |
| `location` | VARCHAR(100) | 否 | NULL | 存放位置 |
| `create_time` | DATETIME | 是 | 当前时间 | 创建时间 |
| `update_time` | DATETIME | 是 | 当前时间 | 更新时间 |

#### 6.6.3 约束设计

| 约束类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `id` | 唯一标识库存记录 |
| 唯一约束 | `book_id` | 一本图书只能对应一条库存记录 |
| 外键 | `book_id` | 关联 `book.id` |
| 非空约束 | `book_id`、`total_quantity`、`available_quantity`、`borrowed_quantity` | 保证库存数量完整 |

#### 6.6.4 索引建议

| 索引名 | 字段 | 类型 | 用途 |
| --- | --- | --- | --- |
| `uk_book_stock_book_id` | `book_id` | 唯一索引 | 根据图书查询库存 |
| `idx_book_stock_available` | `available_quantity` | 普通索引 | 查询可借库存 |
| `idx_book_stock_location` | `location` | 普通索引 | 按存放位置查询 |

#### 6.6.5 业务规则

1. 总数量、可借数量、已借数量不能为负数。
2. 可借数量加已借数量不能大于总数量。
3. 借阅成功时，可借数量减 1，已借数量加 1。
4. 归还成功时，可借数量加 1，已借数量减 1。
5. 可借数量为 0 时不能继续借出。
6. 库存变更应在事务中与借阅或归还记录同步提交。

| `status` | TINYINT | 是 | 0 | 借阅状态：0 借阅中，1 已归还，2 逾期 |
| `fine_amount` | DECIMAL(10,2) | 是 | 0.00 | 罚款金额 |
| `fine_status` | TINYINT | 是 | 0 | 罚款状态：0 未缴纳，1 已缴纳 |
| `remark` | VARCHAR(255) | 否 | NULL | 备注 |
| `create_time` | DATETIME | 是 | 当前时间 | 创建时间 |
| `update_time` | DATETIME | 是 | 当前时间 | 更新时间 |

#### 6.7.3 约束设计

| 约束类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `id` | 唯一标识借阅记录 |
| 外键 | `book_id` | 关联 `book.id` |
| 外键 | `user_id` | 关联 `sys_user.id` |
| 非空约束 | `book_id`、`user_id`、`borrow_time`、`due_time`、`status`、`fine_amount`、`fine_status` | 保证借阅记录完整 |

#### 6.7.4 索引建议

| 索引名 | 字段 | 类型 | 用途 |
| --- | --- | --- | --- |
| `idx_book_borrow_book_id` | `book_id` | 普通索引 | 查询图书借阅记录 |
| `idx_book_borrow_user_id` | `user_id` | 普通索引 | 查询用户借阅记录 |

| `idx_book_borrow_user_status` | `user_id`、`status` | 组合索引 | 查询用户当前借阅 |

#### 6.7.5 业务规则

1. 借阅记录必须关联有效用户和有效图书。
2. 借阅成功后状态为 0 借阅中。
3. 归还成功后记录 `return_time`。
4. 超过应还时间且未归还的记录可视为逾期。
5. 已归还记录不能重复归还。
6. 同一读者对同一本图书存在未归还记录时，可限制重复借阅。
7. 罚款金额默认为 0.00，罚款状态默认为未缴纳。

## 9. 数据完整性设计

### 9.1 实体完整性

1. 所有业务表使用 `id` 作为主键。
2. 主键类型为 BIGINT，自增生成。
3. 主键不可为空且不可重复。

### 9.2 参照完整性

1. `sys_user_role.user_id` 关联 `sys_user.id`。
2. `sys_user_role.role_id` 关联 `sys_role.id`。
3. `book.category_id` 关联 `book_category.id`。
4. `book_stock.book_id` 关联 `book.id`。
5. `book_borrow.book_id` 关联 `book.id`。
6. `book_borrow.user_id` 关联 `sys_user.id`。

### 9.3 业务完整性

1. 用户名、手机号、邮箱不能重复。
2. 角色编码不能重复。
3. 分类编码不能重复。
4. ISBN 不能重复。
5. 库存数量不能为负数。
6. 可借数量加已借数量不能大于总数量。
7. 借阅中的记录必须有借阅时间和应还时间。
8. 归还后的记录应有归还时间。

## 10. 数据一致性设计

### 10.1 图书入库一致性

新增图书时，应同时维护库存记录。若图书保存成功但库存保存失败，应回滚整个操作。

### 10.2 借阅一致性

借阅成功需要同时完成：

1. 创建借阅记录。
2. 扣减 `book_stock.available_quantity`。
3. 增加 `book_stock.borrowed_quantity`。

上述操作应在同一事务中完成。

### 10.3 归还一致性

归还成功需要同时完成：

1. 更新借阅记录状态。
2. 写入归还时间。
3. 更新罚款金额和罚款状态。
4. 增加 `book_stock.available_quantity`。
5. 减少 `book_stock.borrowed_quantity`。

上述操作应在同一事务中完成。

### 10.4 并发一致性

多名用户同时借阅同一本图书时，应防止库存超扣。建议在业务实现中采用以下方式之一：

1. 更新库存时增加条件：`available_quantity > 0`。
2. 使用数据库行锁控制同一本图书库存更新。
3. 使用乐观锁字段扩展库存表。

V1.0 可优先采用条件更新方式，后续高并发场景再扩展乐观锁。

## 13. 逻辑删除设计

### 13.1 适用表

以下表采用逻辑删除：

1. `sys_user`
2. `sys_role`
3. `book_category`
4. `book`

### 13.2 不建议逻辑删除的表

以下表作为关系或流水数据，V1.0 不强制设计逻辑删除：

1. `sys_user_role`
2. `book_stock`
3. `book_borrow`

说明：

1. `sys_user_role` 可随用户或角色关系变更直接删除或重建。
2. `book_stock` 与图书一对一关联，图书逻辑删除后库存不参与正常查询。
3. `book_borrow` 是业务流水，应保留用于历史查询和统计。

## 14. 数据安全设计

1. 用户密码只保存 BCrypt 加密结果。
2. 查询用户信息时不返回 `password` 字段。
3. 普通读者查询借阅记录时必须按当前登录用户 ID 过滤。
4. 管理端查询全局数据前必须校验角色权限。
5. 数据库连接账号应只授予系统运行所需权限。
6. 生产环境不应使用默认数据库密码。

## 18. 设计结论

明月图书借阅管理系统 V1.0 数据库采用 MySQL 和 InnoDB 存储引擎，以 `sys_user`、`sys_role`、`sys_user_role`、`book_category`、`book`、`book_stock`、`book_borrow` 七张核心表支撑系统业务。该设计覆盖用户权限、图书分类、图书信息、库存数量、借阅归还、逾期罚款和基础统计需求，并通过主键、外键、唯一约束、状态枚举、逻辑删除和事务一致性设计保障数据可靠性。

该数据库设计与当前项目实体类和 SQL 草稿保持一致，可作为后续接口设计、详细设计、编码实现和测试验收的基础。
