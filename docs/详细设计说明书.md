# 明月图书借阅管理系统 V1.0 详细设计说明书

## 1. 文档概述

### 1.1 文档目的

本文档基于《PRD 产品需求文档》《系统概要设计说明书》《数据库设计说明书》和《接口设计文档》编写，用于细化明月图书借阅管理系统 V1.0 的后端模块、对象结构、核心方法、业务流程、事务边界、权限控制、异常处理和测试要点。

本文档面向后续编码实现、接口联调、测试设计和软著材料整理，重点说明“如何实现”产品需求和接口设计中定义的业务能力。

### 1.2 设计范围

详细设计覆盖以下范围：

1. 登录认证与登录用户上下文。
2. 用户、角色、权限和系统配置管理。
3. 图书分类、图书资料和馆藏副本管理。
4. 借阅、归还、遗失、逾期和罚款处理。
5. 读者个人中心和基础统计查询。
6. 公共响应、分页、枚举、异常、权限和事务设计。

### 1.3 设计依据

1. `docs/PRD产品需求文档.md`
2. `docs/系统概要设计说明书.md`
3. `docs/数据库设计说明书.md`
4. `docs/接口设计文档.md`

### 1.4 设计口径

1. 图书资料使用 `book_info` 表建模，表示一种图书的书目信息。
2. 馆藏副本使用 `book_copy` 表建模，表示每一册实际可流转图书。
3. 库存数量不维护独立汇总表，统一由 `book_copy.status` 聚合得到。
4. 借阅记录使用 `borrow_record` 表建模，并绑定具体 `copy_id`。
5. 罚款使用 `fine_record` 独立建模，支持逾期、遗失和损坏三类罚款。
6. 权限以 `admin`、`librarian`、`reader` 三类角色为基础，并通过权限编码扩展。

## 2. 总体详细设计

### 2.1 后端分层结构

后端建议采用 Spring Boot 单体应用和分层架构。目标包结构如下：

```text
com.mingyue.bms
  |-- controller          HTTP 接口层
  |-- service             业务接口层
  |-- service.impl        业务实现层
  |-- mapper              数据访问层
  |-- domain
  |    |-- po             持久化对象
  |    |-- dto            请求参数对象
  |    |-- query          查询条件对象
  |    |-- vo             响应视图对象
  |    |-- enums          业务枚举
  |-- common
  |    |-- result         统一响应和分页对象
  |    |-- exception      异常定义和全局异常处理
  |    |-- constant       常量定义
  |    |-- util           通用工具
  |-- security            登录令牌、权限校验、登录用户上下文
  |-- config              Web、MyBatis、跨域、Jackson 等配置
```

### 2.2 层级职责

| 层级 | 主要职责 | 约束 |
| --- | --- | --- |
| Controller | 定义接口路径、接收参数、触发校验、返回统一响应 | 不编写复杂业务规则，不直接访问数据库 |
| Service | 编排业务流程、校验业务规则、控制事务、抛出业务异常 | 借阅、归还、授权等多表操作必须在此层完成 |
| Mapper | 封装数据库访问、分页查询、统计查询和条件更新 | 不处理权限和业务状态机 |
| PO | 与数据库表字段对应 | 不直接暴露给前端 |
| DTO/Query | 承载新增、修改、查询等请求参数 | 配合参数校验注解使用 |
| VO | 返回前端展示数据 | 不包含密码等敏感字段 |
| Security | 解析令牌、保存登录用户、校验角色权限和数据归属 | 读者个人数据以后端登录用户为准 |
| Common | 统一响应、异常、枚举、常量和工具能力 | 保持跨模块复用 |

### 2.3 模块划分

| 模块 | Controller | Service | 主要数据表 |
| --- | --- | --- | --- |

| 馆藏副本 | `BookCopyController` | `BookCopyService` | `book_copy`、`borrow_record` |

## 3. 公共设计

### 3.1 统一响应对象

统一响应对象 `Result<T>`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | Integer | 业务状态码 |
| `message` | String | 响应提示 |
| `data` | T | 响应数据 |

建议方法：

| 方法 | 说明 |
| --- | --- |
| `success()` | 返回成功空对象 |
| `success(T data)` | 返回成功数据 |
| `fail(Integer code, String message)` | 返回失败结果 |

### 3.2 分页对象

分页请求基类 `PageQuery`：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `pageNo` | Integer | 默认 1，最小 1 |
| `pageSize` | Integer | 默认 10，最小 1，建议最大 100 |

分页响应对象 `PageResult<T>`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `pageNo` | Integer | 当前页码 |
| `pageSize` | Integer | 每页数量 |
| `total` | Long | 总记录数 |
| `items` | List<T> | 当前页数据 |

### 3.3 业务枚举

| 枚举 | 值 |
| --- | --- |
| `CommonStatus` | `DISABLED(0)`、`NORMAL(1)` |
| `BookStatus` | `OFF_SHELF(0)`、`ON_SHELF(1)` |
| `BookCopyStatus` | `OFF_SHELF(0)`、`AVAILABLE(1)`、`BORROWED(2)`、`DAMAGED(3)`、`LOST(4)` |
| `BorrowStatus` | `BORROWING(0)`、`RETURNED(1)`、`OVERDUE(2)`、`LOST(3)` |
| `FineType` | `OVERDUE(1)`、`LOST(2)`、`DAMAGED(3)` |
| `FineStatus` | `UNPAID(0)`、`PAID(1)`、`WAIVED(2)` |
| `RoleCode` | `ADMIN`、`LIBRARIAN`、`READER` |

枚举应提供 `code`、`description` 和按编码解析方法，避免业务层散落数字常量。

### 3.4 错误码

错误码使用接口设计文档中的业务错误码。建议定义 `ErrorCode` 枚举，至少包含：

| 错误码 | 触发场景 |
| --- | --- |
| `AUTH_INVALID_CREDENTIALS` | 用户名或密码错误 |
| `AUTH_DISABLED_USER` | 用户被禁用 |
| `AUTH_TOKEN_INVALID` | 登录凭证无效 |
| `PERMISSION_DENIED` | 无权限访问 |
| `USER_USERNAME_EXISTS` | 用户名重复 |
| `USER_READER_NO_EXISTS` | 读者编号重复 |
| `BOOK_ISBN_EXISTS` | ISBN 重复 |
| `COPY_CODE_EXISTS` | 馆藏编号重复 |
| `COPY_NOT_AVAILABLE` | 副本不可借 |
| `BORROW_LIMIT_EXCEEDED` | 超过最大借阅数量 |
| `BORROW_DUPLICATED_BOOK` | 同一图书存在未归还记录 |
| `BORROW_RECORD_NOT_RETURNABLE` | 借阅记录不可归还 |
| `FINE_ALREADY_PAID` | 罚款已处理 |

### 3.5 登录用户上下文

登录成功后，后端从令牌解析出用户 ID，再加载用户状态、角色和权限，封装为 `LoginUser`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `userId` | Long | 用户 ID |
| `username` | String | 用户名 |
| `realName` | String | 真实姓名 |
| `roles` | Set<String> | 角色编码 |
| `permissions` | Set<String> | 权限编码 |
| `status` | Integer | 用户状态 |

`SecurityContext` 通过线程上下文保存本次请求的 `LoginUser`，请求结束后清理。

### 3.6 权限校验

权限校验分两层：

1. 接口权限：通过角色或权限编码判断是否允许访问接口。
2. 数据权限：读者只能访问本人资料、本人借阅和本人罚款。

建议提供：

| 组件 | 说明 |
| --- | --- |
| `RequireRole` | 方法级角色注解 |
| `RequirePermission` | 方法级权限注解 |
| `PermissionChecker` | 统一判断角色、权限和数据归属 |

### 3.7 事务边界

必须开启事务的业务：

1. 新增用户并分配角色。
2. 修改用户角色。
3. 修改角色权限。
4. 新增图书并批量新增馆藏副本。
5. 办理借阅并更新副本状态。
6. 办理归还并更新副本状态、生成罚款。
7. 标记遗失并更新借阅记录、副本状态、罚款记录。

事务传播建议使用默认 `REQUIRED`，业务异常和系统异常均触发回滚。

## 5. 登录认证模块详细设计

### 5.1 模块职责

登录认证模块负责用户登录、退出登录、获取登录用户信息、令牌生成、令牌解析和登录状态校验。

### 5.2 主要类

| 类 | 职责 |
| --- | --- |
| `AuthController` | 提供登录、退出、获取登录用户接口 |
| `AuthService` | 登录认证业务接口 |
| `AuthServiceImpl` | 登录校验、令牌生成、用户权限加载 |
| `TokenService` | 生成、解析和校验访问令牌 |
| `PasswordEncoderService` | 密码加密和密码匹配 |
| `AuthFilter` | 拦截请求并构建登录用户上下文 |

### 5.3 请求和响应对象

| 对象 | 字段 |
| --- | --- |
| `LoginRequest` | `username`、`password` |
| `LoginResponse` | `accessToken`、`tokenType`、`expiresIn`、`userInfo`、`permissions` |
| `CurrentUserVO` | `id`、`username`、`realName`、`roles`、`permissions` |

### 5.4 核心方法

| 方法 | 说明 |
| --- | --- |
| `login(LoginRequest request)` | 校验账号密码，返回访问令牌 |
| `logout()` | 退出登录，可使令牌失效 |
| `getCurrentUser()` | 返回登录用户基础信息 |
| `loadLoginUser(Long userId)` | 查询用户、角色和权限 |

### 5.5 业务规则

1. 用户名和密码不能为空。
2. 用户不存在或密码错误时返回统一登录失败提示。
3. 禁用用户不能登录。
4. 密码使用 BCrypt 或同等级哈希算法校验。
5. 登录成功后更新用户最近登录时间。
6. 响应中不得返回密码字段。

### 5.6 登录伪代码

```text
login(request):
  validate username and password
  user = userMapper.selectByUsername(request.username)
  if user is null or user.isDeleted:
    throw AUTH_INVALID_CREDENTIALS
  if user.status != NORMAL:
    throw AUTH_DISABLED_USER
  if password not match:
    throw AUTH_INVALID_CREDENTIALS
  roles = roleMapper.selectEnabledRoleCodes(user.id)
  permissions = permissionMapper.selectEnabledPermissionCodes(user.id)
  token = tokenService.createToken(user.id)
  update last_login_time
  return LoginResponse(token, userInfo, permissions)
```

## 6. 用户管理模块详细设计

### 6.1 模块职责

用户管理模块负责用户新增、分页查询、详情、修改、启用禁用、删除、重置密码和角色分配。

### 6.2 主要类

| 类 | 职责 |
| --- | --- |
| `UserController` | 用户管理接口 |
| `UserService` | 用户业务接口 |
| `UserServiceImpl` | 用户校验、密码加密、角色绑定 |
| `UserMapper` | 用户表访问 |
| `UserRoleMapper` | 用户角色关系访问 |

### 6.3 请求和响应对象

| 对象 | 字段 |
| --- | --- |
| `UserQuery` | `keyword`、`readerNo`、`status`、`roleCode`、分页字段 |
| `UserCreateRequest` | `username`、`password`、`realName`、`phone`、`email`、`readerNo`、`maxBorrowCount`、`roleIds` |
| `UserUpdateRequest` | `realName`、`phone`、`email`、`readerNo`、`maxBorrowCount`、`status` |
| `PasswordResetRequest` | `newPassword` |
| `UserRoleAssignRequest` | `roleIds` |
| `UserVO` | `id`、`username`、`realName`、`phone`、`email`、`readerNo`、`maxBorrowCount`、`status`、`roles`、`createTime` |

### 6.4 核心方法

| 方法 | 说明 | 事务 |
| --- | --- | --- |
| `pageUsers(UserQuery query)` | 用户分页查询 | 否 |
| `createUser(UserCreateRequest request)` | 新增用户并绑定角色 | 是 |
| `getUserDetail(Long id)` | 查询用户详情 | 否 |
| `updateUser(Long id, UserUpdateRequest request)` | 修改用户资料 | 是 |
| `resetPassword(Long id, PasswordResetRequest request)` | 重置密码 | 是 |
| `assignRoles(Long id, UserRoleAssignRequest request)` | 分配用户角色 | 是 |
| `updateStatus(Long id, Integer status)` | 启用或禁用用户 | 是 |
| `deleteUser(Long id)` | 逻辑删除用户 | 是 |

### 6.5 业务规则

1. 用户名唯一。
2. 读者编号、手机号、邮箱在非空时唯一。
3. 新增和重置密码必须加密存储。
4. 新增用户必须绑定至少一个有效角色。
5. 禁用用户不能登录，也不能新增借阅。
6. 用户存在借阅中记录时不允许删除，应先完成归还、遗失处理或改为禁用。
7. 管理员修改用户资料时不得直接修改密码字段。

### 6.6 新增用户伪代码

```text
createUser(request):
  validate required fields
  check username unique
  check readerNo/phone/email unique if not blank
  roles = roleMapper.selectEnabledByIds(request.roleIds)
  if roles size != request.roleIds size:
    throw PERMISSION_DENIED or parameter error
  user.password = passwordEncoder.encode(request.password)
  insert sys_user
  batch insert sys_user_role
  return user id
```

### 7.5 业务规则

1. 角色编码唯一，权限编码唯一。
2. 禁用角色不参与权限判断。
3. 禁用权限不出现在登录用户可用权限集合中。
4. 已绑定用户的角色不建议删除，可先禁用。
5. `admin` 角色应保留全部系统权限，避免误删导致系统不可管理。

系统配置模块维护基础借阅规则，包括默认借阅天数、默认最大借阅数量和逾期每日罚款金额。

```text
update book_copy
set status = BORROWED
where id = copyId
  and status = AVAILABLE
  and is_deleted = 0
```

若影响行数为 0，说明副本已不可借，抛出 `COPY_NOT_AVAILABLE`。

### 12.7 借阅伪代码

```text
borrow(request):
  reader = userMapper.selectActiveById(request.userId)
  if reader is null or reader.status != NORMAL:
    throw business error

  book = bookInfoMapper.selectActiveById(request.bookId)
  if book is null:
    throw 404
  if book.status != ON_SHELF:
    throw BOOK_NOT_ON_SHELF

  borrowedCount = borrowRecordMapper.countUnreturnedByUser(reader.id)
  limit = resolveBorrowLimit(reader.maxBorrowCount)
  if borrowedCount >= limit:
    throw BORROW_LIMIT_EXCEEDED

  duplicated = borrowRecordMapper.existsUnreturnedBook(reader.id, book.id)
  if duplicated:
    throw BORROW_DUPLICATED_BOOK

  if request.copyId exists:
    copy = bookCopyMapper.selectById(request.copyId)
    validate copy belongs to book and status is AVAILABLE
  else:
    copy = bookCopyMapper.selectFirstAvailableCopy(book.id)
    if copy is null:
      throw COPY_NOT_AVAILABLE

  affected = bookCopyMapper.updateStatusIfAvailable(copy.id, BORROWED)
  if affected != 1:
    throw COPY_NOT_AVAILABLE

  dueTime = request.dueTime or now + borrow.default_days
  borrowNo = numberGenerator.nextBorrowNo()
  insert borrow_record with status BORROWING
  return BorrowCreateResponse
```

### 13.7 归还伪代码

```text
returnBook(request):
  record = borrowRecordMapper.selectById(request.borrowId)
  if record is null:
    throw 404
  if record.status not in BORROWING, OVERDUE:
    throw BORROW_RECORD_NOT_RETURNABLE

  returnTime = request.returnTime or now
  overdue = returnTime > record.dueTime
  targetBorrowStatus = overdue ? OVERDUE : RETURNED
  targetCopyStatus = request.copyStatus or AVAILABLE
  validate targetCopyStatus in AVAILABLE, DAMAGED

  update borrow_record set return_time, status, remark
  update book_copy set status = targetCopyStatus

  if overdue:
    days = calculateOverdueDays(record.dueTime, returnTime)
    amount = days * fine.overdue_daily_amount
    fine = fineService.createOrUpdateOverdueFine(record, days, amount)

  return ReturnResultVO
```

### 14.6 逾期天数和金额计算

逾期天数按服务端时间计算。归还时间晚于应还时间即视为逾期，不足一天按一天计算。

```text
calculateOverdueDays(dueTime, returnTime):
  if returnTime <= dueTime:
    return 0
  hours = ceil((returnTime - dueTime) / 1 hour)
  return ceil(hours / 24)
```

罚款金额：

```text
fineAmount = overdueDays * fine.overdue_daily_amount
```

```text
  borrowedCopyCount = bookCopyMapper.countByStatus(BORROWED)

  overdueCount = borrowRecordMapper.countOverdue(now)
  unpaidFineCount = fineRecordMapper.countByStatus(UNPAID)
  unpaidFineAmount = fineRecordMapper.sumAmountByStatus(UNPAID)
  return DashboardStatisticsVO
```

## 17. 关键业务流程汇总

### 17.1 新书资料和副本入库流程

```text
管理员提交图书资料
  -> 校验 ISBN 唯一
  -> 校验分类有效
  -> 保存 book_info
  -> 管理员提交副本编号列表
  -> 校验副本编号唯一
  -> 批量保存 book_copy
  -> 列表和详情通过 book_copy 聚合库存
```

### 17.2 借阅流程

```text
管理员选择读者和图书
  -> 校验读者状态
  -> 校验借阅数量限制
  -> 校验重复借阅
  -> 校验图书上架
  -> 指定或自动匹配可借副本
  -> 条件更新副本为借出
  -> 创建 borrow_record
  -> 返回借阅单号、应还时间和副本编号
```

### 17.3 归还流程

```text
管理员查询待归还记录
  -> 校验记录可归还
  -> 写入归还时间
  -> 判断是否逾期
  -> 更新 borrow_record
  -> 更新 book_copy
  -> 必要时写入 fine_record
  -> 返回归还结果和罚款信息
```

### 17.4 读者查询本人借阅流程

```text
读者访问我的借阅
  -> 认证过滤器解析登录用户
  -> Service 从登录上下文取得 userId
  -> 按 userId 和状态分页查询 borrow_record
  -> 关联图书资料和副本信息
  -> 返回本人借阅列表
```

## 18. 安全详细设计

### 18.1 认证流程

1. 登录接口不要求认证。
2. 受保护接口必须携带 `Authorization: Bearer <access_token>`。
3. 认证过滤器解析令牌并加载登录用户。
4. 用户不存在、被删除、被禁用或令牌无效时返回 401 或 403。
5. 请求结束后清理登录上下文。

### 18.2 接口权限

| 接口类型 | 允许角色 |
| --- | --- |
| 用户、角色、权限、系统配置 | `admin` |
| 分类、图书、馆藏、副本、借阅、归还、罚款、统计 | `admin`、`librarian` |
| 图书查询、图书详情 | 登录用户，可按业务配置开放 |
| 个人资料、我的借阅、我的罚款 | `reader` |

### 18.3 数据权限

1. 管理员接口可以按业务查询全局数据。
2. 图书管理员不可维护用户角色权限。
3. 读者个人中心接口不信任前端传入的用户 ID。
4. 读者查询本人数据时，统一使用 `SecurityContext.getUserId()`。

### 18.4 密码安全

1. 密码只在新增、登录和重置时出现。
2. 密码必须加密存储。
3. 用户查询、详情和登录用户信息均不返回密码。
4. 登录失败提示不区分用户名不存在和密码错误。

## 19. 异常处理详细设计

### 19.1 异常类型

| 异常 | 使用场景 | 响应码 |
| --- | --- | --- |
| `BusinessException` | 业务规则失败 | 422 或 409 |
| `UnauthorizedException` | 未登录或令牌无效 | 401 |
| `ForbiddenException` | 无角色或无权限 | 403 |
| `NotFoundException` | 数据不存在 | 404 |
| `ValidationException` | 参数校验失败 | 400 |
| `SystemException` | 未知系统异常 | 500 |

### 19.2 全局异常处理

`GlobalExceptionHandler` 统一捕获异常，并转换为 `Result`：

```text
handleValidationException -> code 400
handleUnauthorizedException -> code 401
handleForbiddenException -> code 403
handleNotFoundException -> code 404
handleBusinessException -> code from ErrorCode
handleDuplicateKeyException -> code 409
handleException -> code 500
```

处理原则：

1. 参数错误返回明确字段提示。
2. 业务错误返回业务错误码和可读提示。
3. 系统错误不向前端暴露堆栈。
4. 登录和权限错误应避免泄露敏感信息。

## 20. 数据一致性详细设计

### 20.1 借阅一致性

借阅成功必须满足：

1. `borrow_record` 新增一条借阅中记录。
2. 对应 `book_copy.status` 从可借变为借出。
3. 以上操作同事务完成。
4. 条件更新副本状态成功后才允许创建借阅记录。

### 20.2 归还一致性

归还成功必须满足：

1. `borrow_record.return_time` 写入实际归还时间。
2. `borrow_record.status` 更新为已归还或逾期。
3. `book_copy.status` 更新为可借或损坏。
4. 逾期时 `fine_record` 写入或更新。
5. 任一步失败均回滚。

### 20.3 罚款一致性

1. 同一借阅记录同一罚款类型只保留一条罚款记录。
2. 罚款状态已处理后，不允许重复处理造成状态回退。
3. 已缴纳时间只在状态变为已缴纳时写入。

## 24. 详细设计结论

本详细设计围绕 V1.0 图书借阅核心闭环展开，将图书资料、馆藏副本、借阅记录和罚款记录作为关键业务对象，并通过分层架构、统一响应、统一异常、角色权限、事务控制和状态枚举保证系统可实现、可测试和可维护。

后续开发应优先实现公共能力、登录认证、用户权限、图书资料、馆藏副本、借阅归还和罚款统计等核心链路，再补充页面联调、接口测试和业务流程测试。
